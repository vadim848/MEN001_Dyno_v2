## Q-CA1-01 (средний; MOD-002, WDG-003; этапы E2a/E6) — перезапуск 100 мс подтверждения Run и watchdog 30 с

Источник неоднозначности: Q-RC-RUNCONF-01 «В»: «провал HV до Run — перезапуск отсчёта, **в пределах watchdog 30 с
(E6)**». По E6 30 с идут от C2_FBK ON (t_f) «до получения feedback Healthy». Из ответа не следует, что гасит
watchdog: первый приход Healthy или подтверждение Run (100 мс непрерывно).

Исходно: принят R&D→Run в u, STO снят, C2 ON, C2_FBK ON с t_f = u+1 и держится; кнопки отпущены; нет иных событий.

События:
- (A) `in_HV_Faulty_FBK` FALSE с t_f+10, далее каждые 50 мс TRUE на 1 скан, так что 100 мс непрерывно не набираются
  никогда;
- (B) `in_HV_Faulty_FBK` TRUE до t_f+29949, FALSE с t_f+29950 и держится; Run по RC-5 был бы на t_f+30051.

Чего не хватает:
- **(А)** watchdog 30 с ограничивает только первый приход Healthy и гаснет на нём. (A) — StartingRun длится
  неограниченно (STO снят, C2 ON, Run нет, отката нет); (B) — Run на t_f+30051;
- **(Б)** 30 с ограничивают всё ожидание Run: если Run не подтверждён к t_f+30000, выполняется откат WDG-03
  (Q-RC-12: STO → Discharge → выдержка → C2 OFF → R&D + SafetyFault). (A) — откат на t_f+30000; (B) — откат на
  t_f+30000, Run нет;
- **(В)** иначе.

Рекомендация аналитика — (Б): формулировка «в пределах watchdog 30 с» и отсутствие неограниченного StartingRun со
снятым STO. До ответа: RC-6 для одиночного провала (k+50, 1 скан / 20 мс, граница k+99) — READY. Сценарии (A)/(B) —
наблюдение, BLOCKED только они.

## Не вопросы (решено по источникам, см. дельту)
- Статус Emergency в Safe — L3-Safe (якорь reference в Safe), L2 в Safe не применяется (§2).
- SS1 при Emergency — Imm-выход правила L, нет снятия после e (§3).
- N=u ветка (ii) — окно от первого скана снятия a и эталона `in_Estop_PLC` в StartingRun в a_R+1 (§4).
- Момент Run→Emergency — правило L (L3 ≤ ref+1 = +2), стадии не oracle (§5).
- Q-T3-1 отвечен Вадимом «А» — EMG-RD-L сужен (§6), вопрос закрыт.
