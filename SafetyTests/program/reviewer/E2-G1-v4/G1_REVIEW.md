## 3. Пути Run/R&D ни разу не исполнены на реальной трассе (пункт 2 поручения)

Тестировщик это честно указал. Проверено:

- на reference R&D нет;

### Достаточность самотестов

Самотесты покрывают ядро решения EMGRDL:
- ветка А на границах q_N / q_N+1;
- укорочение q_N−1;
- задержка q_N+2 и «не до цепи»;
- момент цепи Б → FAIL;
- never;
- p.1 буквальное окно с обеих сторон;
- режим AB и смешение;
- p.4 «вышел из цели»;
- «шаг до e не выполнен»;
- окно L1.

Для логики приговора этого достаточно.

**Не покрыто самотестами:**
1. ветка «шаг выполнен в W_N до e и вышел из цели → базовое правило» (см. C2);
2. обвязка emergencyChecks: `descentArea` → `downTa`/`qNrunDown` → EMGRDL → `skip` в L1/L2 → `excl` в L4 — на синтетической трассе;
3. N=u (ii) — не покрыта ни реальной трассой, ни самотестом;
4. сочетание STP-D (C1).

### Риск вакуумности или неверного приговора на кандидате

- **(a) Тихие пропуски.** `profile()` даёт 'absent', если выхода нет в источнике (`OUTPUTS`: «Names absent from a source are skipped»). L1/L2/L3/EMGRDL такие ключи молча пропускают. Если кандидат E2 переименует STO/SS1/Discharge-выход, проверки моментов станут вакуумными.
  - Для стадий есть `STAGES_REQUIRED` с assert. Для выходов аналога нет.
- **(b) Ветка не подтверждена.** EMGRDL печатает только diag `seen`. Ни один тест не утверждает, что в точке свипа реально сработал ожидаемый пункт:
  - p.2 для STO при t_a+1;
  - p.2 для C2 при t_d+T_DIS−1;
  - p.4 в ожидании C2_FBK.

  Если q_N окажется null или ключ уйдёт в «done→base», приговор произойдёт по другому правилу, и это не будет видно.
- **(c) Нет проверки t_a < e.** В `emergencyChecks` для фазы Run-down (`descentArea`) не проверяется t_a < e. Если кандидат принимает down не по удержанию 500 мс, `downTa` найдёт собственную аварийную реакцию (SS1 +3) как t_a. Тогда q_N(STO) = e+2003 — ложный RED.
  - rd-sweep это частично страхует: e строится от t_a no-event трассы.

### Что сделать на G3 (C5)

1. Утвердить присутствие всех `OUTPUTS` (кроме явно необязательных) в кандидате. 'absent' для IMM/DEL → ERROR, не skip.
2. Ledger «утверждение исполнено». EMGRDL возвращает по каждому ключу пункт (p.1 / p.2A / p.4 / done→base / base). Для каждой точки rd-sweep и IL-05d ожидаемый пункт выводится из нормативных соотношений q_N и e+q_R и утверждается. Несовпадение → ERROR стенда.
3. Мутанты, которые обязаны ронять новые проверки (и не только STP-A из E3):
   - (i) при Emergency STO ведётся только таймером аварийной цепи (7 с) — ветка Б → FAIL на t_a+1/+1999;
   - (ii) Emergency перезапускает таймер SS1 или разряда 5 с;

   Выжившие мутанты — в отчёт G3, не скрывать.
4. Положительный контроль на кандидате: в PASS-тестах rd-sweep диагностика должна показывать ветку А. Число исполненных EMGRDL-утверждений — в отчёт.
