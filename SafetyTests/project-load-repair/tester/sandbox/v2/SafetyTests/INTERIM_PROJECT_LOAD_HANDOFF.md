## Прямое решение пользователя

Завершить текущую итерацию с её обязательными проверками и независимым ревью,
затем остановить обычный flow/workflow разработки. Следующую функциональную
итерацию и дальнейшее написание программы не начинать. Следующая задача —
устранить ошибку открытия проекта для промежуточной проверки пользователем
на другом либо текущем компьютере. После исправления загрузки передать результат
пользователю для промежуточной проверки; продолжение функциональной разработки
ждёт его решения. Это не требование немедленно оборвать текущую итерацию.

Ведущий передаёт этот файл редактору с архитектурным анализом причины,
организует независимую проверку исправления и сохраняет ограничения AGENTS.md.
Не менять hardware mappings, NC/NO полярность или поведение ради открытия.
Не выполнять push, deployment, загрузку в контроллер либо управление оборудованием.

## Уже установлено, без заявления об установленной причине

Read-only чтение точного reference commit
`4495a1f6049f6a58ebfd436761faa84d17c8d643` подтвердило:
исходные FBRs1 Reset/Set также содержат `deactivate1="Break Contact (NC)"`;
reference и текущий SAL используют `dslVersion="1.5.0.0"`.
Поэтому глобальная замена этой строки без анализа не обоснована.
Независимый read-only reviewer подтвердил: возможны несовместимость среды
либо некорректный контекст block/port в v2; имеющиеся данные их не различают.
NullReferenceException может быть следствием первого сбоя, это пока гипотеза.
Версии XAE/TwinSAFE Editor и открытие reference на проблемном компьютере
пока не подтверждены. Не объявлять несовместимость версии доказанной причиной.

## Задание и критерий промежуточной готовности

Зафиксировать исходный SHA256 SAL/SGVL и версии доступной среды, сравнить
соответствующие block/port attributes с точным reference, локализовать причину
и внести минимальное обоснованное исправление. Отделить исправление проекта
от необходимых действий установки/версии редактора. Соблюдать разделение ролей
и владение файлами; не ослаблять существующие тесты.

Проверить сохранение программного поведения соответствующими регрессиями.
Главный критерий этой задачи — фактическое открытие Safety_Dyno и
TwinSafeGroup1.sal в TwinSAFE Editor без указанных ошибок. XML/parser/tests
сами по себе этого не доказывают. Если доступ к native editor отсутствует,
передать конкретное исправление и инструкцию проверки пользователю, явно
указать `native opening NOT VERIFIED`; не выдавать проблему за решённую.
Build/Verify/CRC и аппаратная валидация не становятся условиями этой задачи.
