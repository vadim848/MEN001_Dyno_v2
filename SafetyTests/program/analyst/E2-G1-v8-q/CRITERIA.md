## 1. Вопрос 1 — HV Discharge в StartingRun при e ≤ u, когда HV не поднимался (TD-11)

### 1.1 Разбор

- Q-V7-01 «Г» + вопрос 73 «А»: запрос HV Discharge снимается в момент принятия R&D→Run; если переход
  прерывается, «последовательность спуска снова выдаёт Discharge **по своему порядку**». Порядок:
  STO → Discharge → выдержка → C2 OFF.
- При e ∈ [A+1, u] на трассе с событием C2 ни разу не включался, STO ни разу не снимался (инвариант L
  «нет нового повышения в скане ≥ e»). Значит, STO и C2 OFF уже в цели (EMGREF(2), TD-10 §2.2),
  а порядок «STO раньше Discharge, Discharge раньше C2 OFF» выполнен при любом τ ≥ e.
- Нижняя граница L2 Del (d_Run−1 по TD-10) защищает от укороченной выдержки перед разрядом,
  то есть от разряда при ещё вращаемом или питаемом приводе. Здесь привод с R&D не получал момента,
  HV не подключался. Ограничивать раннее повторное выставление разряда нечем.
- Требовать +7009/+7010 означало бы заставить реализацию задерживать снятие энергии. Это против
  принципа 1 (D-TEAM п.1). Аналогия (принцип 2): Q-T3-1 «А» — авария может только ускорить шаг, но не
  задержать; Q-ARCH-03 «Б» — abort StartingRun: «STO → **сразу** Discharge».
- Ответ: **d_Run Run-эталона к HV Discharge как нижняя граница не применяется**, если на трассе с событием
  HV не поднимался. Верхняя граница сохраняется. Это **ослабление oracle** (снята нижняя граница одного
  выхода в узком предусловии), записано как TD-11.

### 1.2 Критерий L2-SU-HV0 (READY-D, TD-11)

Исходное состояние: устойчивый R&D (R0), C3 по базе; BOTH с p, отпускание p+1100; A — по TD-08
(`recRndC_SU` ∨ C2 ON ∨ STO снят, по трассе без события); u — первый выход подъёма трассы без события.

Событие: `in_Estop_PLC` TRUE в e (удерживается), либо причина L1 (NC1, NC2, обе, ES_NC_1/2, Mentee,
connector) в e. e ∈ {A+1, u−1, u} (и любое e ∈ [A+1, u]).

**Предусловие применимости (проверять на трассе с событием, иначе — TD-10 без изменений):**
`out_HV_C2` FALSE и STO_DR1/STO_DR2 активны (не сняты) **в каждом скане ≥ e** до конца наблюдения.
Если хоть в одном скане ≥ e C2 TRUE или STO снят — это FAIL инварианта L, а TD-11 не применяется.

| Выход | Норма | Источник |
|---|---|---|
| `out_HV_Discharge_Request` | τ ≥ e (раньше события — FAIL DIS-HOLD-HV); τ − e ≤ d_Run + 1; после установки TRUE в каждом скане до конца наблюдения (нет принятого подъёма HV) | TD-11; Q-V7-01 «Г»; вопрос 73 «А»; L2 верхняя граница |
| L1 для HV Discharge (X против R = `in_Estop_PLC` в SU, тот же e) | τ_X ≤ τ_R (как Imm); нижней границы нет | TD-11; L1 Imm |
| STO_DR1/2, `out_HV_C2` | в цели в каждом скане ≥ e | EMGREF(2); TD-10 §2.2 |
| `out_LV_C1` OFF | без изменений: TD-10 / TD-12 (§2) | TD-10, TD-12 |
| Imm (статус Emergency, C3/BMS OFF, LV discharge, Unlock FALSE, SS1) | без изменений: L2 Imm, L1 Imm, L4 | §0.1 |
| Защёлка, Restart → только Safe | без изменений | EMG6-01 |

Запрещено: C2 ON или снятие STO в любом скане ≥ e; снятие запроса HV Discharge после его установки
без принятого подъёма; Discharge позже e + d_Run + 1; отсутствие Discharge до конца наблюдения.

Границы: e = A — наблюдение по TD-08 (не входит); e = A+1, u−1, u — нормативно по таблице.
e ≥ u+1 (C2 уже ON или STO уже снят на трассе с событием) — TD-10 без изменений ([d_Run−1, d_Run+1]).
Промежуточный случай «STO снят, C2 ещё не ON» или «C2 ON, STO не снят» TD-11 не покрывает: при
опережении ≥ 2 сканов — вопрос аналитику, не тихий допуск.

Аварийные сочетания: `in_Estop_PLC` и NC1 в одном e — исход как у R; e = u одновременно с первым
выходом трассы без события — нового повышения нет (инвариант L), далее эта таблица.

Ожидание по фактам E2b v7.2 (справка): HV Discharge +7006 при Run +7010 — PASS по TD-11.

## 2. Вопрос 2 — нижняя граница L1-SU для C1 OFF (TD-12, уточняет TD-10)

### 2.1 Разбор

- Факт E2b: `in_Estop_PLC` в SU — C1 OFF +2004 (Run +2005, −1: допуск TD-10); ES_NC_1/2, Mentee в SU —
  +2003, то есть −1 против R(SU): допуск L1.
- **По TD-10 в текущей редакции это FAIL**: TD-10 добавил нижнюю границу d_Run−1 для любой причины в SU.
- Обе разницы — разная латентность путей, а не изменение таймера. Выдержка C1 2 с (Q-ARCH-01 «А»,
  Q-E2Q-01 «А») соблюдена: 2003 ≥ 2000.
- Если сохранить границу d_Run−1, реализации придётся добавить задержку в путь ES_NC/Mentee. Это задержка
  снятия энергии ради oracle, против принципа 1.
- Ответ: **граница TD-10 «для любой причины в SU ≥ d_Run−1» неверна и заменяется**. Нижняя граница —
  композиция двух уже принятых допусков: d_Run−2. Для C1 OFF дополнительно абсолютная граница
  τ − e ≥ 2000. Это **ослабление oracle на 1 скан**, записано как TD-12.

### 2.2 Критерий L1-SU (READY-D, TD-12)

Исходное состояние и StartingRun — как §1.2 / TD-10 §2.2. Причина X ∈ {NC1, NC2, обе, ES_NC_1, ES_NC_2,
Mentee, LV/HV connector} в e ∈ {A+1, u, u+1, u+50, r−1}; R — `in_Estop_PLC` в SU в том же e.

Для Del-выхода o, не достигшего цели до e:

| Проверка | Норма |
|---|---|
| L1 (X против R(SU)) | τ_R − 1 ≤ τ_X ≤ τ_R — без изменений |
| L2-SU (R(SU) против Run) | d_Run − 1 ≤ τ_R − e ≤ d_Run + 1 — TD-10 без изменений |
| Итоговая нижняя граница для X | τ_X − e ≥ d_Run − 2 (вместо d_Run − 1 в TD-10) |
| Только `out_LV_C1` OFF | дополнительно τ_X − e ≥ 2000 (Q-ARCH-01 «C1 OFF через 2 с») |
| Верхняя граница | τ_X ≤ τ_R и τ_R − e ≤ d_Run + 1 — без изменений (отставание запрещено) |

- HV Discharge при предусловии §1.2 — по TD-11.
- Самотест правила (синтетика): для X — −3 → FAIL, −2 → PASS, −1/0 → PASS, отставание от R → FAIL;
  C1 OFF с τ − e = 1999 → FAIL даже при d_Run ≤ 2001; отсутствие выхода → ERROR anti-vacuity.
- Область: только StartingRun. В R&D, R&D→Safe, Safe→R&D, Run→R&D, abort, откатах — L1/L2 прежние;
  опережение там — вопрос аналитику.

Ожидание по фактам E2b (справка): C1 OFF +2003 при Run +2005 (−2), ≥ 2000 — PASS по TD-12.

## 3. Вопрос 3 — маршрут AND6 (existing-retry): входной стимул

### 3.1 Что это за маршрут (canonical F1, прочитано в SAL)

- `inPLC_BypassC1C2` → `Network1/FBAnd4.AndIn1`. `FBAnd4.AndIn2` = `in_False_SI2_CH8` — константа,
  Q-MU06-01 «Б». Далее `FBAnd6` = FBAnd4 ∧ `out_HV_C2` (AndIn2; по unit-тесту — «пока C2 FALSE») →
  `FBOr18.OrIn2` → `FBAndHvSetPermit` → `FBRs2.Set` (`out_HV_C2`).
  Параллельно `FBAnd5` → `FBOr17` — путь LV.
- Это прежний Bypass PLC: V14-Q16 — вход в Config, CFG-001…006, этап E4, заморожен.
  «Повтор» — FBAnd6 снова выставляет Set, пока Bypass TRUE и C2 FALSE.

### 3.2 Входной стимул

`inPLC_BypassC1C2` TRUE, удерживается; `in_False_SI2_CH8` FALSE (константа); прочие входы — по базе.

Справочный замер (модель, `scratchpad bypass.mjs` / `bp3.mjs`, не oracle):

| Источник | Состояние | Bypass TRUE 1500–3000 мс | Итог |
|---|---|---|---|
| F1 | Safe (крышка закрыта, NC1 или NC2 открыта) | C1 0, C2 0, STO не снят, Emergency нет | FBRs2.Reset доминирует |
| E2d v7.4.1 | Safe | C2 0 сканов | — |
| E2d v7.4.1 | R&D | C2 0 сканов | FBAnd4 FALSE |
| E2d v7.4.1 | Run | C2 и так ON | — |

Ни в одном доступном входами состоянии маршрут не даёт **нового** C2 ON. «Existing-retry» в unit-тесте
создаётся вырезанием (FBAnd4.AndOut := TRUE, Reset := FALSE). На уровне входов такого состояния нет.

### 3.3 Норма и статус

- Норма прежняя (E2b-dev §2.3, не заменена): в любом скане n с NC1 или NC2 FALSE нет нового `out_HV_C2` ON
  и нового снятия STO — по любому маршруту. Добавлено: Bypass не обходит крышку (V14-Q16 / CFG-001:
  при открытой крышке Bypass игнорируется без fault).
- **Поведенческие строки FFS-BYP (READY-D, вместо NV):**
  - (a) Устойчивый Safe, кнопки отпущены ≥ 2 с, NC1 (NC2, обе) FALSE с t0, `inPLC_BypassC1C2` TRUE
    с t0+200, удерживается 3000 мс. Ожидается: `out_HV_C2` и `out_LV_C1` FALSE, STO активен в каждом
    скане; Unlock не выдаётся Bypass'ом; нет Emergency/SafetyFault; стадия Safe.
    Источник: V14-Q16 (вход в Config только при NC1∧NC2), CFG-001, V14-Q5.
  - (b) Устойчивый R&D, `inPLC_BypassC1C2` TRUE с t0 и удерживается; BOTH с p ≥ t0+100 → StartingRun.
    NC1 (NC2, обе) FALSE в c ∈ {A−1, A, A+1, u}. Ожидается то же, что в строках TD-08 / COV-1 / FFS
    без Bypass, в том числе «нет нового C2 ON / снятия STO в скане ≥ c». Bypass не меняет исхода.
    Дифференциально: исход с Bypass = исход без Bypass в каждом скане.
    Источник: TD-08, E2b-dev §2.3, V14-Q16 (Bypass вне Safe игнорируется).
  - (c) Если на кандидате в (a)/(b) маршрут где-либо даёт C2 ON, которого нет в контроле без Bypass, —
    это FAIL V14-Q16 / CFG-001: Bypass вне устойчивого Safe игнорируется. Положительное поведение
    Config (C1/C2 ON при закрытой крышке) — **BLOCKED-E4**, здесь не проверяется.
- Unit-пин «existing-retry-AND6 stale aggregate» — структурная проверка F1-подграфа. Переносить ли его
  в V2ID или перенацеливать — решение ведущего и стенда, не аналитика. Поведенческая замена — FFS-BYP.
- Пределы: недостижимость «retry» по входам замерена только в Safe/R&D/Run базах `e2-lifecycle`
  (F1 — только Safe: R&D на F1 недостижим, покрытие). Аварийные и переходные фазы с Bypass TRUE
  не перебирались. Строка (b) это закрывает поведенчески.

## 4. D-V74-1 — REL01-e2-LATE R&D: «принят внутренне, энергии нет, Emergency» (TD-13)

### 4.1 Разбор

- Мера «a» в REL01-e2-LATE (TD-07) у тестировщика — по стадиям или выходам подъёма. TD-08 позже
  определил точку принятия A как самый ранний признак: R&D→Run — `recRndC_SU` ∨ C2 ON ∨ STO снят;
  Safe→R&D — `b_Step12` ∨ C1 ON.
- На E2d v7.4.1 SU стоит на u−2. При s ∈ {Q+2, l0} эпизод крышки начинается после A, но до первого
  выхода. v7.4 блокирует C2 и снятие STO (энергии 0 сканов), затем Emergency.
- По TD-08 это строка «c ≥ A+1 → Emergency, нового повышения в скане ≥ c нет». По REL01-e2-LATE —
  строка «a ≤ s−1 → Emergency обязательна». Исход **не только допустим, он обязателен**.
  Дизъюнкция теста неполна, потому что «принят» в ней измеряется по наблюдаемому подъёму.
- Это **не ослабление**: энергии нет, Emergency есть. Одновременно норма **ужесточается** при A ≤ s−1
  и подъёме ровно в скане s: прежняя строка «l = s — наблюдение» допускала C2 ON в s. Теперь, по
  инварианту L, E2b-dev §2.3 и E2d-COV-1, новое повышение в скане s при FALSE-разрешении в s запрещено.
  Это та же норма, что COV-1 c = u. Кандидат v7.2 (C2 ON в s = l0) по этой строке — FAIL.

### 4.2 Критерий REL01-e2-LATE-A (READY-D; TD-07 + TD-08, запись TD-13)

Исходное состояние, стимулы и точки s — как REL01-e2-LATE (E2-G1-v7-m §1): Safe или R&D, f, p = f+δ,
BOTH до p+1100, эпизод [s, s+100), s ∈ {Q, Q+1, Q+2, Q+401, l0, l0+1}, горизонт ≥ Q+6000.

**a := A** — по TD-08, по трассе без эпизода (fork X0):
- R&D→Run: первый скан ≥ p, где `recRndC_SU` TRUE, или `out_HV_C2` TRUE, или снят STO;
- Safe→R&D: `b_Step12` или `out_LV_C1`.

| Условие | Ожидается | Статус |
|---|---|---|
| A ≤ s−1 | Emergency обязательна (момент — по EMG-004 / Q-RC-03(a) и правилу L). **Нового** повышения (C2 ON, снятие STO, C1 ON) нет ни в одном скане ≥ s. Уже выданное до s остаётся и снимается по аварийной цепи. Допустимы оба варианта: «выход был до s» и «выходов не было вовсе» | READY-D |
| A = s | Наблюдение: (i) отказ без Emergency/fault или (ii) Emergency. В обоих случаях нового повышения в скане ≥ s нет | TD-08 c = A |
| A ≥ s+1 (принятие во время эпизода или после) | запрещено | TD-07 |
| A не наступает | отказ: исходная стадия, ни C1, ни C2, STO не снят, нет Emergency/SafetyFault | EMG-003, IL-02 |
| первый выход подъёма l ≥ s (при FALSE-разрешении в s или позже) | запрещено. Строка «l = s — наблюдение» заменена при A ≤ s−1 | инвариант L Imm; E2b-dev §2.3; COV-1 |

- **Anti-vacuity.** Если Symbol `recRndC_SU` отсутствует и A берётся только по выходам и стадиям, исход
  «Emergency без повышения» при A по выходам ≥ s не засчитывается как PASS: это ERROR предусловия
  (принятие не атрибутировано). Запреты «l ≥ s+1», «подъём после восстановления» и «нет Emergency
  при отказе» проверяются независимо от A. F1 остаётся содержательным RED (подъём на r).
- Нормативные точки: s = Q+401 и s = l0+1 → Emergency (без изменений). s = Q+2 и s = l0 →
  по таблице с a = A. На v7.4.1 ожидается «A ≤ s−1 → Emergency, 0 сканов энергии» — PASS.
- Запрещено (сводно, без изменений TD-07): исполнение удержанного жеста после восстановления;
  «принят без Emergency» при FALSE-разрешении после A; Emergency при неначатом переходе;
  перезапуск паузы 2 с от восстановления.
- Аварийные сочетания: эпизод крышки и `in_Estop_PLC` в одном s при A ≤ s−1 — EMGREF-RUN (общая цепь,
  правило L); эпизод connector в Safe→R&D — EMG4-03-A / EMGREF-LV.

## 6. Пределы

- TD-11 и TD-12 — явные ослабления oracle:
  - TD-11 — снята нижняя граница одного выхода (HV Discharge) при предусловии «HV не поднимался»;
  - TD-12 — нижняя граница Del для L1-причин в SU сдвинута на 1 скан (d_Run−1 → d_Run−2), с абсолютной
    границей 2000 мс для C1.
  Оба ослабления только в сторону более раннего снятия энергии и только в StartingRun.
- TD-13 — не ослабление: согласование меры с TD-08. Для A ≤ s−1 при l = s норма строже прежней.
- Факты кандидатов и замеры маршрута Bypass — модель стенда, не native/target.
