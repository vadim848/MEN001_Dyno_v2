## Q-RC-RUNCONF-01 — от чего считать 0,1 с подтверждения Run (уточнение Q-ARCH-09 «В»)

**Почему вопрос, а не вывод.** Ответ Q-ARCH-09 «В» = «оставить как в v2: Run через 0,1 с при
C2_FBK ON и HV в норме». Но в тексте вопроса (architect/E2-status/PLAN.v2.md, Q-ARCH-09) v2 был
описан как «Run ставится через 0,1 с **после C2_FBK**», а canonical фактически считает 0,1 с
**от команды C2** (N12/FBAnd4 → FBTon3 0,1 с → FBAnd6 ∧ C2_FBK ∧ HV норма). Reference Network5
тоже считает 0,1 с от команды (Step2-AND → N5/FBTon1 0,1 с → FBAnd2 ∧ C1_FBK ∧ C2_FBK), а
непрерывное удержание FBK там давала выдержка 5 с (N5/FBTon2), которую Вадим не восстанавливает.
«Как в v2» и «через 0,1 с после C2_FBK» дают разное поведение — выбрать нельзя без Вадима.

**Исходно:** устойчивый R&D, все разрешения; принят R&D→Run; в скане u — команда C2 ON и снятие
STO (D-STO-LAUNCH). HV Healthy обычно появляется только после замыкания C2.

**События (пример):** C2_FBK ON на u+30 мс; HV в норме (сырое `in_HV_Faulty_FBK` FALSE) с
момента h. k = первый скан, где C2_FBK ON и HV в норме.

**Не хватает:** в какой момент ставится Run.

| Вариант | Run ставится | Пример h=до команды (k=u+30) | Пример h=u+3000 (k=u+3000) | Краткий провал HV (TRUE 20 мс) внутри 0,1 с после k |
|---|---|---|---|---|
| **(а) от команды C2** (canonical сейчас) | первый скан, где прошло ≥0,1 с от команды И C2_FBK ON И HV норма | u+100 (FBK держался 70 мс) | сразу на k (0,1 с уже истекли) — фактической выдержки после HV нет | Run ставится в первом скане ≥u+100 с HV нормой; провал до этого — без последствий |
| **(б) от первого k**, без требования непрерывности | k+100, если в этот момент оба условия есть | u+130 | u+3100 | Run на k+100, если к k+100 HV снова в норме; провал игнорируется |
| **(в) 0,1 с непрерывно** C2_FBK ON ∧ HV норма (план E2a-RC архитектора) | k+100, отсчёт перезапускается при каждом провале | u+130 | u+3100 | отсчёт перезапускается с конца провала; при частых провалах Run может не наступить; нужно знать, продолжается ли watchdog HV 30 с (от C2_FBK ON) — иначе StartingRun может висеть |

**Дребезг C2_FBK** (ON, затем FALSE после первого ON при сохраняющейся команде) во всех трёх
вариантах уже определён Q-RC-19 / FBK-03 (CRITERIA_DELTA_v4): **Emergency**; от выбора не зависит.
Вопрос о провале HV до подтверждения Run влияет только на (б)/(в); в (а) — только если провал
приходится на сам момент ≥u+100.

**Попросить Вадима выбрать (а), (б) или (в).** Для (в) дополнительно: watchdog HV 30 с
продолжает считаться от первого C2_FBK ON при провалах HV (откат на t_f+30000, если Run так и не
подтверждён) — да/нет?

**Зависимое:** временная граница RUN-CONF «нет Run на k+99» и выбор E2a-RC (перестановка
FBAnd6/FBTon3) — BLOCKED до ответа. Независимые части RUN-CONF — READY (CRITERIA.md).
