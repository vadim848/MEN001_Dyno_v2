## 2. Противоречие V14-Q21(b) «как сейчас» с canonical

Факт canonical F1 (структурно, sal-parser): в Run `Network6/FBAnd9` =
EStop-группа ∧ IL_NC1 ∧ IL_NC2 ∧ LV/HV connector ∧ ¬LV/HV Healthy-loss;
FBAnd9 = FALSE → `FBAnd2` → `b_Step4_Set`. Network7 (Step4): DecOut1
`b_Set_LV_Discharge_Request` → FBTon1 **2 s** → `b_Reset_LV_C1_2` →
`Network1/FBOr11` → `FBRs1.Reset` (снятие LV C1); DecOut3/4 `b_C3_BetReset`,
`b_RBN_Bat_Reset`; STO через FBTon2/3 **5 s** после Ton1 (Healthy OK) или
сразу после Ton1 (Healthy lost); `b_Step5_Set` по STO FBK. Network8 (Step5):
Discharge → 1 s → reset C2 → `b_Step6_Set` при ¬C2_FBK. Network9: выход
Step6→Safe отключён (Q-MU06-02). Reference 4495a1f: та же общая цепь Step4→5→6
для всех защитных причин в Run (выход Step6→Safe там рабочий).

Следовательно, «как сейчас» в коде = общая защитная цепь Step4 со снятием
LV через 2 с, сбросом C3/BMS, STO на +7 с и концом не в R&D. Текст ответа
задаёт иное: «защитный спуск в R&D», последовательность Run→R&D
(SS1 → STO → выбег → Discharge → выдержка → C2 OFF). Oracle взят из текста
(R&D, LV сохраняется); подтверждение — Q-RC-01 (высокий приоритет).
Тот же Step4 сейчас обслуживает потерю Healthy в устойчивом Run — реакция
на неё решениями не задана (Q-RC-02).
