# Повторное независимое ревью зелёной кнопки — 2026-10-20

**Подозрение подтверждено в уточнённом смысле:** в текущем SAL обычная команда от зелёной обрабатывается двумя разными механизмами в разных режимах. Это не доказательство двух одновременно принятых команд при одном корректном состоянии. Доказанный дефект — обход памяти попытки в Armed/Run: комбинация двух кнопок превращается в одиночную зелёную без полного отпускания.

Прочитаны отмена предложений Нива в начале SCENARIO_DECISIONS и WORK_STATUS_AND_PLAN, прежние требования Вадима и точный reference. Отменённые предложения не использовались как oracle. Правила проверки: green500, BOTH1000, второй<=250мс, полная очистка попытки, Run BOTH-ignore — ранее согласованные с Вадимом.

## Где два механизма

- **Step1/R&D:** `in_Reset_PB` → `RndPhysicalCompact` (GREEN и память попытки) → `SafeResumption/SG_OWNER_SET` → `STATE_SG`/`recRndC_SG` → `Network12/FBOr2` → команды снижения LV. SG_OWNER_SET запрещает принятие этой команды в Step1; общая область MODE включает только Step1/R&D.
- **Armed/Run:** тот же сырой `in_Reset_PB` → `Network6/FBTon2` (500мс) → `FBAnd24` → `FBAnd23` (разрешение Step3 и синяя OFF) → `FBOr5` → `FBDecouple2` → STO/HV-discharge/C2-OFF requests. Этот путь не использует общую память chord/consumed/rearm. Поэтому сырой зелёный таймер может накопить время при двух нажатых кнопках и разрешить снижение после отпускания синей.

Сравнение с оригиналом существенно: reference имеет сырой Reset в `Network2/FBTon3` с **2с**, выходом в FBAnd4, а также Restart и два входа Decouple. **Armed `Network6/FBTon2` в reference отсутствует.** Называть обнаруженный обход неизменённым унаследованным кодом нельзя; установлен факт сосуществования разных механизмов в v2, а не авторство/история внесения.

## Остальные прямые потребители зелёной

Полный список 17 текущих raw-green consumers записан в JSON по настоящему alias ID. Их наличие само по себе не означает дублирование обычных команд:

- `Network1/FBEstop1/Restart` — отдельное ручное подтверждение EStop.
- `Network1/FBOr3/OrIn4`, `FBAndUnlockHold/AndIn3`, `Network12/FBAnd2/AndIn3` и `RndPhysicalCompact/GATE_031/OrIn3` — снятие/запрет Unlock при зелёной и очистка его памяти.
- `Network1/FBAnd13`, `FBAnd14` — обслуживание ResetPB_Lock; `Network2/FBAnd12` — Step1 и зелёная OFF для исходных запросов C1/C2-OFF. Это условия последовательности, не самостоятельный признанный green-down.
- `RndPhysicalCompact/GATE_002/003/009/025`, `STATE_PrevG` — внутреннее распознавание уровня/попытки/предыдущего состояния.
- `Network1/FBDecouple1/DecIn1/2` — сохранившиеся входы; у выходов этого Decouple нет найденных wire/global потребителей. Двойная запись входов не доказывает две операции.

Отдельные роли Restart и немедленного снятия Unlock допустимы и не устраняются ради единственного raw consumer. Проблема находится в обычном Run-down вне общего владения попыткой.

## Новое независимое воспроизведение

Запуск: `node SafetyTests/button-routing-audit/GREEN_LEGACY_RECHECK.mjs` из корня v2. Использован фактический текущий SAL с реальными цепями выходов и явной границей владельца Step3; PLC00, разрешения исправны, входы не подменены командами. Фиксированный программный scan1мс.

| Последовательность в Run | Наблюдение |
|---|---|
| Обе одновременно t7417, держать400мс, отпустить синюю t7818, зелёную удерживать | Run physical-down t7918, HV-reset request t7920. Нового нейтрального состояния нет — FAIL. |
| Обе одновременно t7417, держать1100мс, отпустить синюю t8518 | Run physical-down сразу t8518, HV-reset t8520 — FAIL по прежнему Run BOTH-ignore. |
| После BOTH отпустить обе, нейтраль2100мс, затем новая зелёная t10619 | Перед новой зелёной physical-down FALSE; новая квалификация t11120 (501мс по наблюдаемым сканам). Положительный контроль отдельной новой зелёной проходит. |

При отпускании обеих также записан краткий physical-down уровень на t8518 вследствие порядка выполнения/сохранённого значения квалификатора; это не скрыто из evidence и не названо вторым независимо доказанным дефектом. Положительный контроль проверяет восстановившееся FALSE до новой зелёной и её последующую квалификацию. Не следует из этого контроля утверждать отсутствие побочных запросов на самом фронте отпускания.
