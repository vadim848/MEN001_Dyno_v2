# E2-G1-v8-r — вопросы

## Q-V8R-01 — индикация `outPLC_RnD` в PLC во время переходных фаз (вопрос Вадиму, через ведущего)

Нужен ответ Вадима: решение меняет то, что видит PLC (D-TEAM-DEFAULTS п.4 «интерфейс с PLC»).
Поведение TwinSAFE от ответа не зависит. Блокируется только отдельная проверка S4 (`E2-G1-v8-r/CRITERIA.md` §1.4).

- **Исходное состояние:** устойчивый R&D (`outPLC_RnD` TRUE).
- **События:** BOTH → R&D→Run принят: C2 включён, STO снят, Run ещё не подтверждён (StartingRun).
  Затем либо Run подтверждается, либо запуск прерывается (зелёная, потеря LV/HV Healthy, watchdog)
  и идёт возврат в R&D: STO → Discharge → C2 OFF → C2_FBK OFF.
  Аналогично в Safe→R&D: C1 включён, R&D ещё не подтверждён.
- **Чего не хватает:** какое значение `outPLC_RnD` должен видеть PLC в StartingRun, во время его прерывания
  и в Safe→R&D. В решениях Вадима это не задано. v1.4 добавляет только STS_COVER_LOCKED; SPEC §14 называет
  STS_TRANSITION_ACTIVE лишь «рекомендуемым».
- **Факт кандидатов E2b/E2d (модель):**
  - StartingRun и прерывание — `outPLC_RnD` TRUE;
  - Safe→R&D — FALSE.
  Внутри TwinSAFE основное состояние в StartingRun — R&D (по SPEC one-hot, Run только после подтверждения).

Варианты:
- **А** — `outPLC_RnD` показывает основное состояние: TRUE в StartingRun и во время его прерывания (Run ещё не
  подтверждён); FALSE в Safe→R&D до подтверждения R&D. Новых сигналов нет. Так сейчас ведут себя кандидаты.
- **Б** — `outPLC_RnD` TRUE только в устойчивом R&D, во всех переходных фазах FALSE. Новых сигналов нет.
- **В** — как А или Б, плюс отдельный сигнал «идёт переход» для PLC. Это новый сигнал интерфейса — этап E4,
  на E2 не реализуется.

Рекомендация аналитика: **А**. Совпадает с one-hot SPEC §14 и текущими кандидатами, интерфейс не меняется.
