## 1. Что меняет ответ Вадима

Дословная суть (SCENARIO_DECISIONS, «Вопрос 76 (KF-5)», ответ «Б»):
- legacy-подъём R&D→Run по коду M = (1,1) отключить уже в E2;
- до E4 R&D→Run — только физический жест BOTH;
- прочие legacy-пути PLC не отключаются: Safe→R&D по (1,0) и спуски. Они остаются известными ограничениями до E4;
- изменение поведения PLC Вадим подтвердил.

Отключается всё, что legacy-путь P2 (N12/FBAnd10 → N12/FBOr1 → FBAnd4, PLAN v7 §13) давал через код (1,1):
- команда C2;
- подтверждение Run и снятие STO;
- снятие запроса HV Discharge (DIS-HOLD, источник `b_Set_HV_C2_1`);
- вход в SR.

Как отключить — решение архитектора. В v7.2 он предлагал точку N12/FBOr1.OrIn2; это справка, не oracle.

Ответ не трогает:
- P1 — N2/FBAnd91 → g2, Safe→R&D по (1,0);
- спуск Run→R&D по (0,1) — N6/FBAnd17 (¬M1 ∧ M2 ∧ Run);
- уровни M в Run на `out_SS1_DR1/2` через N1/FBAnd2 (Run ∧ ¬M1 ∧ ¬M2), см. §6 «Попутно».

Обоснование — в самом ответе Вадима: короткий импульс (1,1) < 600 мс оставлял R&D с C2 ON, снятым запросом разряда и без выхода кнопкой (KF-5).

## 2. Нормативные запреты для (1,1)

Общая норма N0 (READY-Q76). В E2 код M = (1,1) — не команда R&D→Run.
- Ни в каком состоянии и ни при какой длительности, фронте или уровне он не даёт подъёма HV.
- Он не снимает `out_HV_Discharge_Request`.
- Он не меняет `out_Step*` в сторону подъёма.
- Он не ставит SafetyFault и Emergency.

Каждый сценарий ниже — конкретизация N0 для тестов. Исходное состояние по умолчанию R-RND:
- устойчивый R&D: `out_Step12` TRUE, C1 ON, C1_FBK ON, LV в норме;
- C2 OFF, C2_FBK OFF, STO установлен на обоих приводах;
- `out_HV_Discharge_Request` TRUE (вариант: FALSE, если запрос с boot не выдавался — тогда «не меняется»);
- крышка закрыта (NC1 ∧ NC2), EOk, connectors в норме, HV Faulty FALSE;
- нет SafetyFault, M = (0,0), кнопки отпущены ≥ 2100 мс.

### Q76-N1 — бывший KF-5: импульс (1,1) любой длины в R&D (READY-Q76)

ID: MOD-002, MOD-007, STP-004, MOD-005, MOD-006.

**Последовательность.**
- M = (1,1) с t на w мс, затем (0,0).
- w ∈ {1, 50, 300, 499, 500, 501, 599, 600, 601, 1500}, плюс вариант «удержание 10000 мс».
- Значения 499/500/501 — граница окна C2 500 мс. 599/600/601 — бывшая граница подтверждения Run (TD-02, RUN-CONF-T). На E2 их ожидание одинаково; они ловят частично восстановленный путь.
- C2_FBK вариантами:
  - (i) OFF всё время;
  - (ii) «следует команде C2 через 1 скан» — стенд не должен его выдать, команды нет;
  - (iii) ON без команды с f = t−3000 — это поглощённый FBK10-PLC-B, см. Q76-N2.
- Вариант V75-1, переход (1,0)→(1,1): устойчивый R&D, полученный по legacy (1,0) или по BOTH, M = (1,0) удерживается ≥ 2100 мс; в t M2 := TRUE (код (1,1)), далее как выше (импульс w и удержание). Ожидание то же. Отдельно граница: M2 TRUE в r−1, r, r+1 относительно первого скана S12 после Safe→R&D по (1,0) — подъёма нет до r+3000.

**Ожидается: каждый скан [t, t+10000].**
- стадия S12 (`out_Step12` TRUE), SR и S3 нет;
- `out_HV_C2` FALSE и `b_Set_HV_C2_1` FALSE;
- STO_DR1 и STO_DR2 установлены;
- `recRndC_SU` FALSE;
- `out_HV_Discharge_Request` равен значению до t, без перерыва;
- `out_LV_C1` TRUE, без изменений;
- нет Emergency, нет SafetyFault от (1,1).

Вариант (iii): SafetyFault от FBK-10 ставится по Q-V4-02 — это его собственный критерий, (1,1) его не меняет.

**Затем.** M = (0,0) ≥ 100 мс, кнопки отпущены ≥ 2100 мс, зелёная 0,5 с в t+10000 → R&D→Safe по MOD-005.
К t+25000: Safe, C1 OFF, C2 OFF.

**Запрещено:**
- любой скан с подъёмом HV в [t, t+25000];
- R&D с `out_HV_C2` TRUE (STP-004, SPEC стр. 527);
- `out_HV_Discharge_Request` FALSE в любом скане, если до t был TRUE;
- отсутствие Safe с C1/C2 OFF к t+25000 после зелёной;
- Emergency как единственный выход.

Источники: вопрос 76 «Б»; DIS-HOLD Q-V7-01 «Г» + вопрос 73 «А» (снятие только принятием подъёма, а (1,1) подъём не принимает); MOD-005.

Отличие от прежнего KF-5 (E2-plan-v7-TD §3): исход (а) «Run по RUN-CONF-T» стал запрещённым. Нормативен только исход (б) — причём с первого скана, а не к t+10000.

### Q76-N2 — (1,1) при C2_FBK ON без команды: бывший FBK10-PLC-B (READY-Q76; FBK — READY-D)

ID: MOD-008, MOD-002, MOD-007, WDG-004.

**Исходно.** R-RND. С f C2_FBK ON без команды C2.

**Последовательность.**
- M = (1,1) с t ∈ {f+1, f+100, f+3000}, удержание 1500 мс, затем (0,0).
- Варианты продолжения:
  - (a) FBK OFF в g = f+3000, а M держится через g до g+1000 (бывший KF-1 для (1,1));
  - (b) FBK OFF в g, затем новый фронт (1,1) в g+2100 на 1000 мс без квитирования кнопкой (бывший KF-1 для (1,1)).
- Граница: фронт (1,1) в g−1, g, g+1.

**Ожидается: каждый скан [t, конец + 1500].**
- стадия R&D, нет SR/Run;
- `out_HV_C2` FALSE, `b_Set_HV_C2_1` FALSE;
- STO установлен;
- `out_HV_Discharge_Request` TRUE.

**Запрещено:**
- подъём HV в любом скане, в том числе после g и в границах g−1/g/g+1;
- Emergency из-за FBK-10 (Q-V4-02 «Не Emergency»).

SafetyFault по FBK-10 — по Q-V4-02 / Q-V7-04, этим критерием не нормируется (E5).

Отличие от прежнего FBK10-PLC-B: запрет теперь держится не на гейте FBK-10, а на отключении. Поэтому он действует и после FBK OFF.

### Q76-N3 — (1,1) при нажатой кнопке: бывший KF-2 для (1,1) (READY-Q76)

ID: PLC-004, MOD-007.

**Исходно.** R-RND.

**Последовательность.**
- Синяя нажата 1500 мс (это Unlock в R&D — по его критериям).
- (1,1) фронтом в press+100:
  - вариант «импульс 200 мс внутри нажатия»;
  - вариант «удержание до release+1500».
- Тот же сценарий с зелёной: 400 мс, не квалифицирована как одиночная. Квалифицированная зелёная — это R&D→Safe (MOD-005), см. Q76-N1 «Затем».

**Ожидается.** Подъёма HV нет до release+3000. `out_HV_Discharge_Request` TRUE.

**Запрещено:** подъём HV во время нажатия и после отпускания.

Источник: вопрос 76; V14-Q14 «А» (для (1,1) теперь избыточно).

### Q76-N4 — (1,1) при активной SafetyFault: бывший KF-1 для (1,1) (READY-Q76)

ID: WDG-004, MOD-008, MOD-007.

**Исходно.** R-RND с активной SafetyFault любой причины:
- FBK-10 после FBK OFF без квитирования;
- конец окна C2 без FBK по Q-V7-03 / E6-Q1, после отката в R&D.

**Последовательность.** (1,1) фронтом, импульс 50 мс и удержание 3000 мс.

**Ожидается.** Подъёма HV нет. `out_HV_Discharge_Request` TRUE. SafetyFault по (1,1) не снимается: PLC не квитирует (E6-Q2).

**Затем.**
- Квитирование BOTH-1 только квитирует (E6-Q2, Q-V7-04).
- Новый BOTH-2 после отпускания ≥ 2001 мс поднимает (TD-06: u ≤ Q2+400).
- (1,1), удерживаемый всё это время, ни квитирования, ни подъёма не добавляет.

**Запрещено:**
- подъём HV до BOTH-2;
- снятие SafetyFault кодом (1,1).

### Q76-N5 — (1,1) выставлен в Safe и удерживается через Safe→R&D: часть KF-3 (READY-Q76)

ID: MOD-003, PLC-001, MOD-007.

**Исходно.** Устойчивый Safe (R-T5 из E2-plan-v7-TD §1), без Emergency.

**Последовательность.**
- M = (1,1) с t0, удерживается.
- BOTH в t0+200 на 1100 мс → Safe→R&D (кнопочный, Q-RC-18(b): состояние PLC кнопки не блокирует).
- r — первый скан стадии S12 после подтверждения R&D.
- (1,1) держится до r+3000, затем (0,0).
- Граница: фронт (1,1) в r−1, r, r+1 (отдельные прогоны, M = (0,0) до фронта).

**Ожидается.**
- Safe→R&D исполняется кнопкой, как без (1,1): (1,1) в Safe — не код (1,0), P1 не срабатывает;
- в [r, r+3000+1500] подъёма HV нет, запрос HV не снимается.

**Запрещено:**
- подъём HV после r;
- отказ Safe→R&D из-за удерживаемого (1,1).

Отказ Safe→R&D — READY-D: (1,1) больше не команда (вопрос 76); ошибка/состояние PLC физический жест не блокирует (Q-RC-18(b) «А»).

### Q76-N6 — бывший KF-3-DESC: (1,1) удерживается через спуск Run→R&D (READY-Q76)

ID: MOD-003, PLC-001, STP-004, MOD-002, MOD-007.

**Исходно.** Устойчивый Run, **поднятый жестом BOTH**: прежняя база «Run по legacy (1,1)» на E2 недостижима.
- C2 ON, C2_FBK ON, HV норма, STO снят;
- крышка закрыта, EOk, кнопки отпущены ≥ 2100 мс.
- M = (1,1) выставлен в Run в t0 ≤ t_a − 2100 и удерживается.

**Последовательность.**
- Зелёная 0,5 с → принят Run→R&D. t_a — скан установки `linkRunDownOwner` (определение V73-A / PLAN v7.3 D-E2b-3(а)).
- M = (1,1) держится до t_a+10000, затем (0,0).
- r — первый скан стадии S12 после спуска.

**Ожидается.**
- Спуск идёт по STP-001/STP-004. Моменты не нормируются здесь.
- Каждый скан [r, t_a+10000]:
  - стадия R&D, нет SR/Run;
  - `out_HV_C2` FALSE;
  - STO установлен;
  - `out_HV_Discharge_Request` TRUE (Q-V7-01 «Г»).

**Запрещено:**
- повторный вход в SR/Run;
- C2 ON;
- снятие STO;
- снятие запроса HV уровнем (1,1).

**Границы.** Фронт (1,1), выставленный впервые в r−1, r, r+1 (M = (0,0) в Run) → то же ожидание до r+3000.

**Бывший положительный контроль заменён.**
- Прежде: «после (0,0) 600 мс новый фронт (1,1) принимается».
- Теперь это **запрет**: после (0,0) 600 мс новый фронт (1,1), удержание 1500 мс → подъёма HV нет до +3000.
- Положительный контроль — BOTH после отпускания ≥ 2100 мс → R&D→Run (Q76-P1).

### Q76-N7 — (1,1) во время StartingRun, начатого BOTH (READY-D)

ID: STP-006, MOD-004, MOD-002, MOD-007.

**Исходно.** R-RND. BOTH → принят R&D→Run (SU, C2 ON, STO снят), стадия SR.
- Вариант «SR длительный»: HV Faulty TRUE с t0−100 держит SR (как бывший тест KF-4).
- M = (1,1) с a+x, x ∈ {1, 100, 1000}, удерживается. a — скан установки SU.

**Последовательность и ожидания.**

(a) Без события. Ход SR и момент Run не зависят от (1,1).
- Норма — неравенство: в каждом скане (1,1)-трасса не имеет подъёма HV или Run там, где их нет у контрольной трассы с M = (0,0) (тот же кандидат, тот же жест).
- Обратное — более раннее снятие энергии — не запрещено этим пунктом.

(b) Abort зелёной 0,5 с в SR (V14-Q12; D-STARTINGRUN-NO-COAST). (1,1) держится до +10000 после прихода в R&D (r).
- Каждый скан [r, r+10000]: R&D, C2 OFF, STO установлен, запрос HV TRUE, повторного SR/Run нет.
- Нормы моментов самого abort — STP-006 (E3). На E2 abort кнопкой в SR — по его собственным критериям; этот пункт нормирует только отсутствие повторного подъёма.

(c) Откат по окну C2 (E6-Q1: нет C2_FBK за 500 мс) при удержании (1,1).
- После возврата в R&D повторного подъёма нет до квитирования и нового BOTH.

**Запрещено.** (1,1) создаёт, продлевает или возобновляет SR/Run, C2 ON или снятый STO после abort/отката.

**Источник.** Вопрос 76: единственный источник R&D→Run — BOTH. Повторный подъём без нового жеста запрещён BTN-/MOD-003 («новый жест для каждого шага»).

Почему READY-D, а не READY-Q76: SR здесь начат кнопкой. Норма — «(1,1) ничего не добавляет».

### Q76-N8 — (1,1) с Emergency и крышкой (READY-Q76; аварийная цепь — по EMG-критериям)

ID: EMG-011, MOD-002, MOD-007, CVR-004.

**Emergency.**
- Исходно R-RND. Источник Emergency в e (`in_ES_NC_1` / `in_ES_NC_2` / `in_Mentee_EStop` FALSE); E — первый скан `b_EStop_Ok` FALSE.
- (1,1) фронтом в E−1, E, E+1, удержание 3000 мс; вариант — через Restart.
- **Ожидается:**
  - ни одного скана подъёма HV;
  - запрос HV TRUE без перерыва;
  - аварийная цепь — по EMG-критериям;
  - после Restart стадия Safe, и удерживаемый (1,1) не даёт ни S12, ни подъёма.

**Крышка.**
- R-RND, NC1 FALSE (вариант NC2) с c.
- (1,1) в c+50 на 300 мс, затем крышка закрывается при (1,1) удерживаемом либо уже снятом.
- **Ожидается:** подъёма HV нет до +3000, запрос HV TRUE.
- Тот же результат дают бывшие тесты DIS-HOLD (B)/(C) (PLAN v7 §4.2); их ожидания не меняются.

## 3. Положительные контроли

### Q76-P1 — BOTH по-прежнему поднимает R&D→Run (READY; TD-06, RUN-CONF-T, DIS-HOLD-HV)

ID: MOD-002, BTN-006.

**Исходно.** R-RND, M = (0,0).

**Последовательность.** BOTH δ = 0 на 1100 мс; C2_FBK следует команде через 1 скан; HV норма.

**Ожидается.**
- нет подъёма в [p, Q−1];
- u ∈ [Q, Q+400] (TD-06);
- Run — по RUN-CONF-T (вопрос 68 «Б», TD-02);
- `out_HV_Discharge_Request` FALSE не позже u+1 (DIS-HOLD-HV, вопрос 73 «А»).

Назначение: отключение (1,1) не должно задеть кнопочный путь (SU → N12/FBOr1.OrIn1).

### Q76-P2 — BOTH при удерживаемом (1,1) (READY-D)

**Исходно.** R-RND. M = (1,1) с p−3000 (вариант: с p+500, внутри жеста) до p+5000.

**Ожидается.**
- то же, что Q76-P1: подъём кнопкой исполняется, моменты u и Run те же (±0 сканов к контрольной трассе с M = (0,0));
- после прихода в Run — без повторов.

**Источники.**
- вопрос 76 — (1,1) не команда, значит не конфликт и не второй источник;
- Q-RC-18(b) «А» — состояние/ошибка PLC физический BOTH не блокирует;
- V14-Q14 — игнорируется PLC-фронт, а не кнопка.
