# REQ-CONSOLIDATION — критерии по ID (решения Вадима 2026-10-21)

Срез / роль / дата: REQ-CONSOLIDATION / v2-analyst / 2026-10-21.
Источник: canonical F1 SAL 04b45456…8a3, SGVL dc103abe…9104, diagram de02bbff…a603;
SCENARIO_DECISIONS 42aaf5db…62e4 (HEAD ea6b52d). Трассировка решений — TRACE.md;
предложение по перечню ID — SCOPE_PROPOSAL.md; вопросы — QUESTIONS.md.

Это критерии требований, не план реализации: имена внутренних маркеров,
блоков и новых сигналов PLC↔TwinSAFE выбирает архитектор. Наблюдаемые точки
указаны по смыслу (команда C1/C2 ON/OFF, STO, SS1, Discharge, Unlock, статусы).

## 0. Общие условия и обозначения

**Статусы:** READY — oracle однозначен из решений/требований; READY-D —
выведен из утверждённого требования (указано какого), без нового поведения;
BLOCKED(Q-RC-xx) — ждёт ответа; BLOCKED(ARCH) — Вадим делегировал выбор
архитектору, поведение возвращается аналитику после проекта.

**R0 (исходные входы):** все входы заданы явно (E0: незаданный вход = ошибка):
in_ES_NC_1/2 TRUE, in_InterLock_NC_1/2 TRUE, LV/HV connector TRUE, Mentee FALSE,
in_Estop_PLC / CMD_TRIGGER_EMERGENCY FALSE, in_False_SI2_CH8 FALSE (Q-MU06-01:
константа), кнопки FALSE, in_Door_Monitor TRUE, все CMD_* FALSE, Bypass FALSE,
heartbeat переключается каждые 500 мс, Healthy «исправно» (полярность сырого
входа — по архитектору: в canonical сырое FALSE = исправно), feedback
контакторов/STO следуют командам по модели стенда, если не сказано иное.
Скан 1 мс.

**Устойчивые состояния** достигаются реальными producers (жест или фронт
команды PLC от Safe), затем кнопки отпущены ≥ 2000 мс; не инъекцией Set.

**Таймеры:** T_SINGLE 500, T_BOTH 1000 (от второй), T_WINDOW 250 включ.,
T_RELEASE 2000, T_SS1 2000, T_COAST 5000, T_DIS — существующая выдержка
разряда (Network8; в SAL FBTon1/FBTon2 по 1 s; точная точка отсчёта — по
маппингу архитектора, число не менять), T_CMDERR 1000 (V14-Q10),
T_HB 3000 / период 500 (V14-Q20), T_FBK 500, T_HEALTHY 30000 (E6).

**Границы q−1/q/q+1:** q — первый скан, на котором порог по требованию
истёк. q−1 и q+1 нормативны; поведение ровно в q нормативно только если
требование задаёт «не позднее/включительно» (окно 250 мс), иначе q фиксируется
как наблюдение по документированной семантике TON (E0), не FAIL.

**EMGREF (дифференциальный oracle «→ Emergency»):** аварийная последовательность
выходов и защёлка совпадают с реакцией на `in_Estop_PLC`/`CMD_TRIGGER_EMERGENCY`
TRUE в том же состоянии и том же скане (решения: «как в любом состоянии»,
V14-Q19; «переход в Emergency (защёлка…)», V14-Q20). Плюс общие обязательные
свойства: статус Emergency, ни одного нового повышения энергии/снятия STO,
Unlock FALSE, выход только ручным Restart по EMG6-01. Точная аварийная
последовательность discharge (SPEC §16 п9) этим не задаётся.

## A. E2 — однозначный статус, конфликт → Emergency

**E2-01 (READY) — один основной статус всегда.** Во всех трассах этого
документа и полного регресса в каждом скане активно ровно одно из
{Emergency, Safe, R&D, Run, Config}; переходные фазы (StartingRun, StoppingSS1,
STOCoastWait, HVDischarging, HVDisconnecting, StoppingToSafe, откат E6, выход
Config) принадлежат ровно одному переходу и не маскируются под основное.
Запрещено: два основных одновременно хотя бы 1 скан (включая Step3∧Step4
1 скан, Step4∧Step12, найденные E1). Источник: E2 «исключить … одновременного
владения двумя стадиями»; V14-Q16 (Config включён); SPEC §14; MOD-006.

**E2-02 (READY) — гонка E1 даёт единственный исход R&D.** Исходно: Run;
принят down (зелёная удерживается / отпущена после принятия на 550 и 800 мс /
фронт CMD_RUN_TO_R&D); последовательность дошла до ожидания C2_FBK OFF после
команды C2 OFF. События: потеря LV Healthy (вариант L) или HV Healthy
(вариант H) в скане h; C2_FBK OFF впервые в h+d, d ∈ {1,2,3,4,5}.
Ожидается: каждый скан один статус (E2-01); итог R&D; затем (L) R&D→Safe по
HLT-01, (H) устойчивый R&D. Запрещено: Step4∧Step12, LV-запрос в защитной
фазе, возврат в Run. Этот тест обязан убить MU11 (условие C3 ревью E1).
Источник: E2-Q1, E2-Q2; находка E1 (architect PLAN §4, reviewer §c).
На canonical ожидается RED.

**E2-03 (READY, условно на архитектуру) — обнаруженный конфликт → Emergency.**
Если архитектура сохраняет раздельные памяти состояний, инъекция двух
основных одновременно (как STATE:conflicting-set-requests) → EMGREF,
защёлка, выход только EMG6-01. Если однозначность по построению (одна
кодированная память), инъекция неприменима — заменяется структурным
доказательством недостижимости, ревьюер оценивает. Источник: E2.

**E2-04 (BLOCKED Q-RC-10)** — ни одного основного статуса вне переходной фазы.

## B. E3 — STOP v2 (Run→R&D) и abort StartingRun

Общее для B: исходно устойчивый Run (StartingRun → Run подтверждён), C2_FBK ON,
LV ON, Healthy исправны, кнопки отпущены ≥ 2000 мс.
t_a — скан принятия down (зелёная: квалификация на p+500, принятие по
маркеру архитектора; PLC: фронт CMD_RUN_TO_R&D в скане e).

**STP-A (READY) — нормальная остановка зелёной.**
| Момент | Ожидается | Запрещено |
|---|---|---|
| t_a (+≤1 скан) | SS1 запрошен обоим приводам; C2/LV ON; Unlock FALSE | STO, Discharge, C2 OFF |
| t_a+1999 | STO ещё не активирован | Discharge, C2 OFF |
| t_a+2000 (q) / +2001 | STO активирован (обязателен к q+1) | Discharge |
| t_s+4999 (t_s — скан STO) | нет команды Discharge | C2 OFF |
| t_s+5000 / +5001 | команда Discharge (отдельная, обязательна к q+1) | C2 OFF в том же скане |
| t_d+T_DIS−1 | C2 ещё ON | C2 OFF |
| t_d+T_DIS / +1 | команда C2 OFF | — |
| C2_FBK OFF в t_c+k (k=1,50,400) | R&D со скана после C2_FBK OFF; LV ON | R&D раньше C2_FBK OFF |
Во всей последовательности: Unlock FALSE; LV C1 не снимается; BOTH и
CMD-UP не принимаются и не исполняются позже (MOD-004); один статус (E2-01).
Источник: E2-Q1 «Уточнение Вадима к последовательности Run→R&D», D-RUN-STOP-WAITS,
D-HV-TIMED-COMPLETE, V14-Q3 (это и есть «zero speed/current»), SPEC §8/§10.
На canonical F1 ожидается RED: Network6 RUN_DOWN_OWNER→FBOr5→FBDecouple2
выдаёт Discharge, Reset C2 и сброс STO одновременно (находка E1).

**STP-B (READY) — тот же oracle для фронта CMD_RUN_TO_R&D** (t_a = e или
e+1 по маркеру). Источник: V14-Q3 «одинаково к физической кнопке и к PLC», V14-Q11.

**STP-C (READY) — отказ C2 OFF.** В STP-A/B C2_FBK остаётся ON после команды
C2 OFF (t_c): t_c+499 — без Emergency, R&D не объявлен; t_c+501 — EMGREF.
Источник: E6-Q1 «Отказ при отключении … Emergency»; STP-004.

**STP-D (READY) — потеря HV Healthy во время SS1.** Healthy потерян в
h ∈ {t_a+1, t_a+1000, t_a+1999}. Ожидается: STO в h (≤ h+1 скан), не ждать
t_a+2000; Discharge не раньше h+5000 (полный выбег от STO); восстановление
Healthy в h+100 не возвращает SS1 и не сокращает выбег; fault
HealthyLostDuringSS1 зафиксирован; далее Discharge → T_DIS → C2 OFF → C2_FBK OFF →
R&D; fault сбрасывается изменением уровня любой кнопки после завершения.
Источник: SPEC §9, EMG-008/009, D-HEALTHY-FAULT-RESET-EDGE, ответ «Healthy30с
… не к потере Healthy при SS1». Предел: discharge при Healthy FALSE —
SPEC §16 п3 (аппаратное), программный порядок §9 п6–7.

**STP-E (READY) — abort StartingRun.** Исходно: R&D, принят R&D→Run, STO снят
(D-STO-LAUNCH), Run ещё не подтверждён. Событие в скане a: (1) новая
зелёная 500 мс после полной очистки (обе отпущены ≥ 2000 мс); (2) фронт
CMD_RUN_TO_R&D. Ожидается: STO в a (≤ a+1); команда Discharge сразу после STO
(не позже a+2, без ожиданий 2000/5000 — проверка на a+1999 обязательна:
Discharge уже есть); без SS1; C2 OFF не раньше t_d+T_DIS; R&D после C2_FBK OFF.
Запрещено: SS1-запрос, Run (даже если C2_FBK ON и Healthy придут после a),
возобновление запуска, повтор UP без нового события.
Граница с подтверждением Run (скан r): событие в r−1 → abort (STP-E); в r+1 →
нормальная STP-A/B; в r — наблюдение.
Источник: D-STARTINGRUN-GREEN-DOWN, D-STARTINGRUN-NO-COAST, V14-Q12.

**STP-F (BLOCKED Q-RC-09)** — потеря Healthy после STO (выбег/выдержка разряда),
кроме фазы ожидания C2_FBK OFF (= E2-02, READY).

**STP-G (BLOCKED Q-RC-02)** — потеря LV/HV Healthy в устойчивом Run без
принятого down (сейчас — общая цепь Step4).

## C. Потеря InterLock NC1/NC2 по состояниям (V14-Q21)

Варианты нарушения для всех C: NC1 FALSE; NC2 FALSE; оба; при Door TRUE и FALSE.
EStop-каналы in_ES_NC_1/2 этим разделом не затрагиваются.

**IL-01 (READY) — Safe.** NC FALSE → нет Emergency, нет fault; Safe→R&D по
BOTH и по фронту CMD_SAFE_TO_R&D **принимается** (позитив, MOD1-01);
вход в Config запрещён (CFG-02). Источник: V14-Q21(a), V14-Q7.

**IL-02 (READY) — R&D.** NC FALSE → нет Emergency/fault, R&D и LV сохраняются;
BOTH и фронт CMD_R&D_TO_RUN отклоняются без fault; после восстановления NC
удерживаемый CMD/продолженное удержание кнопок не исполняется — нужен новый
жест/фронт. Скан-границы: NC FALSE в N, UP-фронт в N−1 (→ StartingRun, см.
IL-05), N, N+1 (отклонён). Источник: V14-Q21(a), V14-Q5, V14-Q11, CVR-004.

**IL-03a (READY) — Run, общее для обоих прочтений.** NC FALSE в t: нет
защёлки Emergency (Restart не требуется); SS1 до STO (STO не раньше t+2000);
Discharge до C2 OFF; Unlock FALSE; восстановление NC в t+100 не возвращает
Run (новое UP требует нового события). Источник: V14-Q21(b), MOD-003.

**IL-03b (BLOCKED Q-RC-01) — Run, точная последовательность и конечное
состояние.** Текст ответа: спуск в R&D по STP-A (LV сохраняется). Код
«как сейчас»: Step4 (LV C1 снимается через 2 с, C3/BMS сброс, STO через 7 с,
конец не R&D).

**IL-04 (READY) — Config.** NC FALSE (каждый вариант, 1 скан достаточно) → EMGREF.
Источник: V14-Q16, V14-Q21(c).

**IL-05 (BLOCKED Q-RC-03)** — StartingRun; прочие переходные фазы (Run→R&D
спуск, Safe→R&D, R&D→Safe, выход Config).

## D. Config (V14-Q16…Q19)

**CFG-01 (READY) — вход, позитив.** Устойчивый Safe, NC1∧NC2 TRUE, R0. Bypass
FALSE→TRUE в скане b и удерживается. Ожидается: Config; команды C1 и C2 ON
(порядок — архитектор; к каждой применяется T_FBK); STO активен всё время
Config; Unlock FALSE; один статус. Источник: V14-Q16.

**CFG-02 (READY) — вход, игнор.** Bypass TRUE (фронт) в R&D, Run, StartingRun,
Safe→R&D, R&D→Safe, Run→R&D спуске, Emergency, Safe с NC1/NC2/обоими FALSE:
ни одной команды C1/C2 ON сверх текущих, нет смены состояния, нет fault.
Источник: V14-Q16 «В любом другом состоянии/при открытой крышке команда
игнорируется».

**CFG-03 (BLOCKED Q-RC-05)** — Bypass, выставленный раньше (уровень), при
достижении устойчивого Safe / закрытии крышки; Bypass при нажатой кнопке,
одновременно с CMD_*, при активной SafetyFault/ошибке PLC; вход без
connectors. Предложение аналитика (не oracle до ответа): только фронт
(MOD-003), прочие разрешения как для UP (EMG-003/011, V14-Q14).

**CFG-04 (READY) — в Config всё прочее игнорируется.** В Config по очереди:
зелёная 500/2000 мс, синяя 500/2000 мс, BOTH 1000 мс, фронты всех четырёх
CMD_*, in_C3_Manual_Set, in_RBM_Manual_Set. Ожидается: Config сохраняется, C1/C2
ON, STO активен, Unlock FALSE весь интервал, нет SafetyFault. После
отпускания кнопок/сброса команд — нет отложенного исполнения.
Источник: V14-Q16 «все прочие команды кнопок и PLC игнорируются»; V14-Q15
(C3/BMS только R&D/Run).

**CFG-05 (READY) — удержание без автоотключения.** Bypass TRUE 9999/10000/10001/
60000 мс: Config и C1/C2 ON сохраняются. Запрещено: сброс C1/C2 по 10 с
(N1/FBTon1 удалён). Источник: V14-Q17.

**CFG-06 (READY) — выход.** Bypass TRUE→FALSE в x (также импульс FALSE 1 скан).
Ожидается: команда Discharge (≤ x+1 скан) раньше любой команды OFF контактора;
нет OFF контактора до t_d+T_DIS (q−1 запрещено, q+1 обязательно); вариант A:
C2 OFF, затем C1 OFF только после C2_FBK OFF; вариант B: C1 и C2 OFF в одном
скане ≥ t_d+T_DIS; Safe только при C1_FBK OFF ∧ C2_FBK OFF; без SS1, STO
активен весь выход; Unlock FALSE до Safe. Bypass снова TRUE во время выхода —
игнорируется (не устойчивый Safe), выход продолжается. FBK ON > 500 мс после
OFF → EMGREF (WDG-05). Источник: V14-Q18, E6-Q1. Архитектор фиксирует вариант
A или B; тест проверяет выбранный и инварианты обоих.

**CFG-07 (READY) — аварии в Config.** ES_NC_1 FALSE; ES_NC_2 FALSE;
in_Estop_PLC/CMD_TRIGGER_EMERGENCY TRUE; Mentee TRUE; LV connector FALSE;
HV connector FALSE; NC1/NC2 (IL-04); heartbeat 3 с (HB-02) → EMGREF.
LV Healthy и HV Healthy: потеря на 1 скан, 5 с, переключение 100 мс в течение
10 с → игнорируется: Config, C1/C2 ON, нет fault/Emergency/SafetyFault.
Источник: V14-Q19, V14-Q20.

**CFG-08 (BLOCKED Q-RC-06)** — отказ T_FBK при входе в Config (C1/C2 без FBK ON
за 500 мс): откат в Safe+SafetyFault или Emergency.

## E. Команды PLC (V14-Q8…Q14, V14-Q4, V14-Q5)

Команды по v1.4 §8: CMD_SAFE_TO_R&D, CMD_R&D_TO_RUN, CMD_R&D_TO_SAFE,
CMD_RUN_TO_R&D (команды перехода), CMD_TRIGGER_EMERGENCY; статус STS_COVER_LOCKED;
статус ошибки PLC (имя/агрегация — архитектор, см. Q-RC-13).

**PLC-01 (READY) — позитив по фронту в исходном устойчивом состоянии.**
Для каждой команды: исходное состояние команды, кнопки не нажаты, нет ошибки
PLC, нет SafetyFault (для UP), прочие разрешения. Фронт в e → переход принят
(скан принятия фиксирует архитектор, ≤ e+2). Safe→R&D — и при NC FALSE
(V14-Q7); R&D→Run — только NC1∧NC2; R&D→Safe — по MOD5-01; Run→R&D — STP-B.
Также сразу после Emergency→Safe (V14-Q4). Источник: V14-Q11, V14-Q4, V14-Q7.

**PLC-02 (READY) — удерживаемая команда не повторяется.** (a) CMD_SAFE_TO_R&D
фронт → R&D, удерживается; зелёная → Safe; 2500 мс после Safe: нет Safe→R&D.
(b) CMD_R&D_TO_RUN удерживается через Run→R&D: после R&D 2500 мс нет StartingRun.
(c) CMD_R&D_TO_SAFE удерживается через BOTH Safe→R&D: R&D сохраняется 2500 мс.
(d) CMD_RUN_TO_R&D удерживается через R&D→Run: StartingRun не прерывается,
Run не покидается. Источник: V14-Q11, MOD-003.

**PLC-03 (READY) — фронт вне исходного состояния игнорируется без ошибки.**
Каждая команда, фронт в каждом не-исходном устойчивом состоянии и в
переходной фазе (кроме исключений PLC-10), затем удерживается до прихода в
её исходное состояние: нет перехода, нет статуса ошибки, нет SafetyFault.
Источник: V14-Q11. UP в переходах — MOD-004.

**PLC-04 (READY) — одновременные фронты → ошибка.** В каждом устойчивом
состоянии (Safe, R&D, Run) две и более команды перехода FALSE→TRUE в одном
скане e (все 6 пар, 4 тройки, четвёрка; включая пару, где одна валидна).
Ожидается: ни одна не исполнена (состояние/выходы неизменны), статус ошибки
PLC TRUE не позже e+1, не меняет текущее состояние. Источник: V14-Q8.

**PLC-05 (BLOCKED Q-RC-04)** — перекрытие уровней без общего скана фронтов
(одна удерживается, вторая поднимается позже); ошибка в Config/переходах.

**PLC-06 (READY) — снятие ошибки.** После PLC-04 все команды FALSE с f.
Ошибка TRUE на f+999, снята на f+1000 (q) / обязательно на f+1001. Импульс
любой команды 1 скан в f+500 → ошибка держится, снятие на (f+500)+1+1000;
сам импульс не исполняется. После снятия одиночный фронт в исходном
состоянии исполняется (PLC-01); удерживавшаяся до снятия команда — нет.
Кнопки на ошибку не влияют (физ. квитирование не требуется).
Источник: V14-Q10, V14-Q11.

**PLC-07 (READY) — CMD_TRIGGER_EMERGENCY всегда.** В Safe, R&D, Run, Config,
каждой переходной фазе, при активной ошибке PLC, при SafetyFault, при
нажатых кнопках, в одном скане с любыми командами перехода → EMGREF;
сопутствующая команда перехода не исполняется; пара TRIGGER+одна команда
статус ошибки PLC не создаёт («в правило V14-Q8 не входит»). Источник: V14-Q9,
V14-Q19, SPEC §13.

**PLC-08 (READY) — кнопка нажата → PLC-фронт игнорируется навсегда.** Для
каждой команды перехода и каждой кнопки (зелёная < и ≥ 500 мс, синяя < и ≥
500 мс с Unlock TRUE, обе): фронт при нажатой кнопке → не исполнен, после
отпускания не исполнен, без ошибки. Границы: кнопка отпущена в скане r
(FALSE в r): фронт в r−1 → игнор; в r → исполняется (если прочие условия).
Источник: V14-Q14 (2-с фильтр для PLC не задан, кроме E6-Q2 после квитирования).

**PLC-09 (READY) — исключения для переходов.** (a) CMD_RUN_TO_R&D в StartingRun →
STP-E. (b) Safe→R&D принят, C1 ON, R&D не установлен: фронт CMD_R&D_TO_SAFE
или новая зелёная 500 мс → C1 OFF, ожидание C1_FBK OFF, Safe; не возобновляется
(удерживаемый CMD_SAFE_TO_R&D и позднее пришедшие C1_FBK/LV Healthy не дают R&D).
Граница с установлением R&D (скан r): событие в r−1 → abort; в r+1 → обычный
R&D→Safe (тот же конечный Safe, один статус). SafetyFault этим abort не
требуется и не запрещается (не задано). Источник: V14-Q12, V14-Q13.

**PLC-10 (BLOCKED Q-RC-08)** — DOWN-команды/зелёная в прочих переходных фазах.

**PLC-11 (READY) — STS_COVER_LOCKED = NC1∧NC2.** Все 4 комбинации NC × Door
TRUE/FALSE × каждое состояние (вкл. Emergency, Config): статус = NC1∧NC2,
от Door не зависит; задержка — один скан или документированная архитектором.
Источник: V14-Q5.

**PLC-12 (READY) — PLC не открывает крышку и не снимает Emergency.** Перенос
E4-v14 C07/C08 на новые сигналы: перебор команд/Bypass/heartbeat в Emergency
и в Safe/R&D/Run при отпущенной синей — Unlock FALSE; Emergency не снимается.
Источник: V14-Q4, V14-Q6, EMG-006, CVR-001.

**PLC-13 (READY-D) — прежний 2-битный путь не создаёт переходов.** После
замены интерфейса inPLC_RnD_Mode/_2 (если остаются в группе) не вызывают
переходов, SS1 и Set. Источник: V14-Q2 «изменить нынешний подход на тот, который
описан в документе». Ветвь N12/FBAnd14 — Q-MU06-02.

## F. Heartbeat (V14-Q20)

**HB-01 (READY) — исправный heartbeat ничего не делает.** Переключения через
500 мс и с неравными интервалами до 2999 мс в каждом состоянии и фазе: нет
Emergency, нет переходов. Источник: V14-Q20.

**HB-02 (READY) — таймаут → Emergency.** Последняя смена уровня в t, далее
залипание TRUE или FALSE: t+2999 — нет Emergency; t+3000 (q) / t+3001 — EMGREF
обязателен к q+1. В Safe, R&D, Run, Config, StartingRun, Run→R&D, Safe→R&D.
Источник: V14-Q20 «действие во всех состояниях, включая Safe и Config» (как
пункт проекта) + общий ответ «после таймаута — переход в Emergency».

**HB-03 (READY) — защёлка.** Возобновление heartbeat после HB-02 не снимает
Emergency; снятие только EMG6-01. Restart зелёной при не возобновлённом
heartbeat → Emergency сохраняется (SPEC §12 п1 «Устранена причина»).

**HB-04 (BLOCKED ARCH)** — старт группы до первого импульса (делегировано
архитектору Вадимом; поведенческий выбор вернуть аналитику).

## G. Watchdog E6 и SafetyFault

**WDG-01 (READY) — Safe→R&D, нет C1_FBK ON.** Команда C1 ON в t_on.
C1_FBK ON в t_on+499 → продолжение. Нет FBK к t_on+500 (q) / t_on+501 →
откат: команда C1 OFF, C1_FBK OFF, Safe, SafetyFault TRUE; не Emergency.
FBK, пришедший после начала отката, R&D не даёт. Источник: E6, E6-Q1.

**WDG-02 (READY) — Safe→R&D, нет LV Healthy.** C1_FBK ON в t_f. Healthy в
t_f+29999 → R&D. Нет Healthy к t_f+30000 / +30001 → откат как WDG-01 +
SafetyFault. До R&D: Unlock FALSE, R&D не объявлен. Источник: E6, E6-Q1.

**WDG-03 (READY-D) — R&D→Run, нет C2_FBK ON за 500 мс / нет HV Healthy за
30 с от C2_FBK ON.** Откат в R&D последовательностью abort StartingRun (STP-E:
STO → Discharge → T_DIS → C2 OFF → C2_FBK OFF → R&D) + SafetyFault; не Emergency;
Run не устанавливается. Выведено: «по его обычной последовательности
снятия» + единственная согласованная последовательность снятия из
StartingRun (D-STARTINGRUN-NO-COAST). Подтверждение — Q-RC-12 (низкий).

**WDG-04 (READY) — 30 с не применяется к SS1.** Потеря Healthy в SS1 → STP-D,
не WDG. Источник: ответ «Healthy30с относится к startup readiness».

**WDG-05 (READY) — отказ при отключении → Emergency.** Каждая команда OFF
C1/C2 (R&D→Safe, STP-A/B/E, откат WDG-01..03, PLC-09b, выход Config, аварийная
последовательность): FBK ON на t_off+499 → без Emergency и без целевого
состояния; FBK ON на t_off+501 → EMGREF. Уже в Emergency: остаётся, выход
EMG6-01 невозможен, пока FBK ON (SPEC §12 п4). Источник: E6-Q1.

**WDG-06 (READY) — квитирование SafetyFault.** Исходно: SafetyFault после
WDG-01/02 (Safe) или WDG-03 (R&D), кнопки отпущены. (a) Нажатие зелёной
(1 скан и 600 мс) или синей (1 скан и 600 мс) → SafetyFault FALSE со скана
нажатия; нет перехода, нет Unlock, удержание не становится командой.
(b) Новая попытка: обе отпущены непрерывно 1999 мс → жест отклонён;
2000 мс → обычный жест принимается. (c) PLC: никакой сигнал PLC не снимает
SafetyFault; фронт UP-команды при активной SafetyFault не исполняется и не
исполняется после квитирования (нужен новый фронт после 2000 мс отпускания
кнопок). (d) Пока активна: BOTH UP не исполняется. (e) CMD_TRIGGER_EMERGENCY и
EStop работают (PLC-07). Источник: E6-Q2, п.13 (2026-10-21).

**WDG-07 (BLOCKED Q-RC-07)** — DOWN от PLC (CMD_R&D_TO_SAFE) и Bypass при активной SafetyFault.

## H. Healthy в R&D (E2-Q2)

**HLT-01 (READY) — потеря LV Healthy в R&D → Safe.** Устойчивый R&D, LV Healthy
потерян устойчиво (≥ 100 мс) в h: R&D→Safe — C1 OFF, C3/BMS OFF (если были
включены вручную), C1_FBK OFF → Safe; не Emergency. Восстановление Healthy
после h не возвращает R&D. 1-сканный провал — наблюдение (порог не задан).
Источник: E2-Q2(a), D-LV-OFF-COMPLETE, V14-Q15.

**HLT-02 (READY) — HV Healthy в R&D игнорируется.** Устойчивый R&D; HV Healthy
постоянно «исправно», постоянно «потерян», переключается 100 мс: нет перехода,
нет fault/Emergency; приём R&D→Run (BOTH/CMD) от значения HV Healthy до
запуска не зависит. Источник: E2-Q2(b), v1.4 §4.

**HLT-03 (BLOCKED Q-RC-11)** — нужен ли статус/квитирование ошибки при HLT-01.

## I. Emergency → Safe (V14-Q6)

**EMG6-01 (READY).** Источники по отдельности: ES_NC_1/2, in_Estop_PLC/
CMD_TRIGGER_EMERGENCY, Mentee, heartbeat (HB-02), NC в Config (IL-04), connector
после Safe (EMG-004), WDG-05, E2-03. После устранения причины, при снятой
энергии и FBK OFF: нажатие+отпускание зелёной (in_Reset_PB → Restart) → Safe;
не R&D/Run/Config, даже если CMD_* удерживаются (не фронт). Гриб нажимать не
требуется при PLC/Mentee-источнике. Restart при активной причине или FBK ON →
Emergency сохраняется. Никакая комбинация PLC-сигналов Emergency не снимает.
Источник: V14-Q6, решение №12, SPEC §12, EMG-005/006. Bypass, удерживаемый
через Restart, — Q-RC-05.

**EMG6-02 (READY)** — после EMG6-01 фронт CMD_SAFE_TO_R&D (выставленный после
прихода в Safe) исполняется как PLC-01. Источник: V14-Q4.

## J. Safe→R&D / R&D→Safe содержимое

**MOD1-01 (READY).** Safe→R&D (BOTH или CMD): команда C1 ON; C1_FBK ON
(≤ 500 мс), LV Healthy (≤ 30 с от FBK) → R&D. C3/BMS автоматически не
включаются; R&D достигается без их feedback; C2 OFF и STO активен; Unlock
FALSE во время перехода; NC1/NC2 FALSE не мешают. Источник: V14-Q7, V14-Q15, E6, SPEC §6.

**MOD5-01 (READY).** R&D→Safe (зелёная 500 мс или фронт CMD_R&D_TO_SAFE):
C1 OFF, C3/BMS OFF, C1_FBK OFF → Safe (раньше — нет); C1_FBK ON > 500 мс → EMGREF.
Источник: D-LV-OFF-COMPLETE, V14-Q15, E6-Q1, SPEC §11.

**MOD-C3 (READY).** in_C3_Manual_Set / in_RBM_Manual_Set действуют только в R&D
и Run; в Safe и Config игнорируются; при R&D→Safe и Emergency выключаются.
Источник: V14-Q15, V14-Q16.

**MU06-S (READY, структурно).** Ветви N5/FBAnd7, N9/FBAnd1, N12/FBAnd14 при
in_False FALSE не дают выхода (или удалены архитектором); проверки при
in_False TRUE вне объёма. Источник: Q-MU06-01/02.
