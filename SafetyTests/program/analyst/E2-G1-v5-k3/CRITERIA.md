## 1. Вывод: однозначно, вопрос Вадиму не нужен

Первый BOTH после FBK OFF без квитирования **только квитирует** SafetyFault. Подъёма в этом жесте нет. Подъём возможен только новым жестом после непрерывного отпускания обеих кнопок 2 с.

Основание (цепочка):
1. **Q-V4-02 «В»:** для FBK-10 «квитирование по E6-Q2». Отдельного механизма нет.
2. **Вопрос 66(a):** SafetyFault — одна память, причины общие; снятие по E6-Q2.
3. **E6-Q2 «А»:** нажатие любой кнопки квитирует SafetyFault и **потребляет попытку — само ничего не запускает**. Новая попытка — после того, как обе отпущены непрерывно 2 с, новым жестом. Пока ошибка активна, UP не исполняются.
4. **Подтверждение п.13 «РЕШЕНО» (Вадим «Подтверждаю такой вариант»):** продолжение того же удержания после квитирования не превращается в обычную команду; нужны обеOFF 2 с и новая попытка. Квитирование — сразу при нажатии, без удержания и ожидания отпускания.
5. **Q-RC-07:** единственное исключение «квитирует и выполняет» — квалифицированная зелёная вниз (R&D→Safe). Для подъёма Q-RC-07 прямо повторяет: подъём при активной SafetyFault запрещён. На BOTH/UP исключение не распространяется.
6. **WDG-06 (a)(b)** уже утверждённых критериев: SafetyFault FALSE со скана нажатия, нет перехода, удержание не становится командой. Новая попытка — по границе отпускания 2000 мс.

Уточнение формулировки тестировщика. В HANDOFF_v5 сказано: «квитирование завершается только отпусканием на 2 с». Точнее:
- SafetyFault гаснет со скана первого нажатия (п.13, WDG-06(a));
- 2 с отпускания — условие **новой попытки**, а не момент квитирования.

На вердикт k3 это не влияет: подъём в том же жесте запрещён при любом прочтении.

## 2. Критерий K3-ACK (READY)

### Обозначения
- f — первый скан FBK TRUE без команды (как §4.5);
- g — первый скан FBK FALSE после эпизода (основной вариант g = f+3000);
- p — скан первого нажатия жеста BOTH-1;
- δ — задержка второй кнопки, δ ∈ {0, 250} мс;
- Q1 = p+δ+1000 — скан, в котором BOTH-1 был бы квалифицирован;
- r — первый скан, в котором обе кнопки отпущены после BOTH-1;
- p2 — первое нажатие BOTH-2;
- Q2 = p2+δ+1000.

### Исходное состояние
Как CRITERIA_DELTA_v7 §4.5:
- **(S1)** устойчивый Safe, событие C1_FBK; **(S2)** то же, C2_FBK;
- **(R)** устойчивый R&D, событие C2_FBK;
- кнопки отпущены непрерывно с момента ≤ f−2000 до p;
- прочие разрешения подъёма присутствуют все: LV/HV норма, interlock NC1/NC2 TRUE, нет EStop/Emergency, нет PLC-ошибки, R0;
- до f нет SafetyFault.

### Последовательность входов
1. FBK TRUE в [f, g−1], FALSE с g.
2. Квитирования нет: ни кнопки, ни PLC-фронтов в [f, p−1].
3. BOTH-1:
   - синяя-первая и зелёная-первая (симметрично);
   - первая кнопка в p, вторая в p+δ;
   - обе удерживаются до Q1+100 (≈ BOTH 1100 мс);
   - вариант длинного удержания — до Q1+4000.
4. Отпускание обеих; r — первый скан, когда обе FALSE.
5. BOTH-2 в p2 (по границам п.«Граница паузы»), удержание 1100 мс.

### Обязательные точки p
- **p = g+2100** — основной вариант теста k3;
- **p = g+1** — первый скан после FBK OFF;
- **p = g** — FBK FALSE и нажатие в одном скане. READY-D: в этом скане FBK уже OFF, поэтому это k3, а не k4.

p ≤ g−1 (нажатие, пока FBK ON) — это k1/k4, BLOCKED Q-V7-04. Здесь не судить.

### Ожидается
| Что | Окно | Источник |
|---|---|---|
| SafetyFault TRUE | [f+1, p−1]; FBK OFF в g её не гасит | Q-V4-02, E6-Q2, §4.5 k3 |
| SafetyFault FALSE | с [p, p+1] и далее до конца трассы. Проверка NV до символа (A8) | п.13 «сразу», WDG-06(a). READY-D по моменту (q/q+1) |
| Подъём BOTH-1 **не исполняется** | каждый скан [p, p2−1] и при длинном удержании. **(S1/S2):** C1 ON не выдан, STO не снят, статус Safe, нет начала Safe→R&D. **(R):** C2 ON не выдан, STO_DR1/2 не сняты, SS1 не меняется, статус R&D, нет StartingRun | E6-Q2 «потребляет попытку», п.13 РЕШЕНО, Q-RC-07 |
| Нет спуска | (R) зелёная-первая с δ ≤ 250 — это BOTH-попытка, не квалифицированная одиночная зелёная. R&D→Safe нет, C1 не снимается | п.6/п.7 2026-10-21 (chord), Q-RC-07 только для квалифицированной зелёной 0,5 с |
| Нет Emergency, энергия и состояние неизменны | весь интервал | Q-V4-02 «не Emergency» |
| Unlock FALSE | во время BOTH-1 | WDG-06(a)/(a') |
| BOTH-2 при p2 ≥ r+2001 **исполняется** | (S1/S2) начало Safe→R&D — C1 ON; (R) начало R&D→Run — C2 ON или снятие STO. ~~в [Q2, Q2+1]~~ **заменено TD-06 (E2-G1-v6-q): нет подъёма ≤ Q2−1, первый подъём в [Q2, Q2+400], точный скан — наблюдение**; далее штатно | E6-Q2 «новым жестом», п.9 (2 с), §4.5 k2 |

### Граница паузы (BTN-001, REL-01(d), WDG-06(b))
Пауза отсчитывается от r. Начало BOTH-1 не является началом паузы — п.9: «не отсчитывать паузу при ещё удерживаемой кнопке».
- p2 = r+1999 → BOTH-2 отклонён: нет подъёма, нет fault, SafetyFault остаётся FALSE. Для следующей попытки снова нужны 2 с.
- p2 = r+2000 → наблюдение. REL-01(d) v4 пометил его наблюдением, WDG-06(b) v2 — «принимается». Берётся более поздняя и более слабая пометка.
- p2 = r+2001 → исполняется.

### Запрещено
- подъём в любом скане BOTH-1, включая Q1, Q1+1 и длинное удержание (FAIL «квитирование совмещено с подъёмом»);
- подъём при отпускании одной кнопки из BOTH-1 или из «оставшейся» одиночной (п.7, п.10);
- отсчёт паузы 2 с от p или от Q1 вместо r;
- SafetyFault TRUE после p+1 без нового FBK-эпизода (NV до A8);
- Emergency, изменение энергии/состояния из-за FBK-10 или квитирования.

### Сопутствующие варианты (READY, той же нормой)
- **PLC вместо кнопок:** после g фронт CMD_SAFE_TO_R&D ((R): CMD_R&D_TO_RUN) без квитирования кнопкой → не исполняется, SafetyFault остаётся TRUE. Источник: E6-Q2 «PLC не квитирует», WDG-06(c).
- **PLC после квитирования BOTH-1:** новый фронт PLC-команды после квитирования исполняется. Условие E6-Q2: «новым фронтом команды PLC». Фронт, поднятый до p и удерживаемый, не исполняется (WDG-06(c)). Нужен ли и для PLC-фронта отсчёт 2 с отпускания кнопок от r — **наблюдение**, нормы нет. Вне вопроса k3, в тест не вносить как oracle.
- **Аварийные:** in_Estop_PLC/EStop в любой точке [f, Q2] → Emergency по EStop (EMGREF), как §4.5. Квитирование не отменяет аварийный приоритет.

### Мутант (C5)
**(xvi)** квитирующее нажатие не потребляет попытку: BOTH-1 после FBK OFF квитирует и поднимает в Q1. Ожидается kill на S1/S2 p = g+2100 и p = g+1.
Мутант (xiii) из v7 — другой: он убирает условие FBK OFF, но не потребление попытки.
