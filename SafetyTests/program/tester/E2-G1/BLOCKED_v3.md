## Внутри среза E2 — заблокировано вопросом

| Критерий | Блок | Что не хватает (исходное состояние → событие → реакция) |
|---|---|---|
| UNL-04 с `in_Door_Monitor` FALSE | **Q-T3-2 (новый, аналитику)** | Safe/R&D, крышка открыта, Door FALSE, синяя ≥ 500 мс. CRITERIA_DELTA_v4 UNL-04 в исходном состоянии допускает «Door TRUE/FALSE», но действующая роль DoorMonitor для Unlock сохранена (AGENTS, D-DOOR-INTERLOCK), а одобренный тест `current-unlock-hold.test.js` (стр. 54) требует: Door FALSE → Unlock FALSE в Safe. Нужен ответ: при Door FALSE Unlock TRUE (UNL-04 буквально) или FALSE (сохраняемая роль DoorMonitor)? Написан только вариант Door TRUE |
| Нижняя граница L2 для Del-выходов в фазах, где нормальный спуск уже ведёт выход к цели (Run-down: SS1/выбег) | **Q-T3-1 (новый, аналитику)**, допущение A11 | Run-down (зелёная принята), `in_Estop_PLC` в e. Буквальное L2 требует STO не раньше e+τ_Run (≈+7006), хотя нормальный спуск активирует STO раньше. Нужен ответ: сохраняется ли ранний STO нормального спуска (нижняя граница не применяется) или аварийная цепь перезапускает выдержку? Сейчас верхняя граница нормативна, нижняя — только diagnostic, и только для выходов, которые no-event продолжение достигает раньше τ_Run |
| Q-V4-01 (дребезг FBK в окне 500 мс), Q-V4-02 (FBK ON без команды) | Q-V4-01/02 | FBK-* вне объёма v3 |
