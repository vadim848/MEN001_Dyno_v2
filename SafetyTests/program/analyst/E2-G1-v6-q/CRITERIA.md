## 1. Единая норма момента начала подъёма после BOTH (TEAM-DEFAULT TD-06)

### Что найдено
- **Квалификация жеста** (BTN-006, T_BOTH 1000 мс от второй кнопки): принятые тесты 03B (`src/current-gesture-boundaries.js`) меряют её на внутреннем сигнале квалификации — нет на q−1 (999 мс), есть на q+1 (1001 мс).
- **Начало перехода на выходах** (C1 ON / C2 ON / снятие STO) после квалификации ни одним решением Вадима, требованием или reference **не задано по скану**:
  - DIS-HOLD-HV/LV (E2-plan-v5-questions §1): [a, u] — наблюдение, u = первый скан выхода подъёма;
  - REL-PERMIT, REL-01(b)(c)(d) (`current-e2d-release-permit`): «принят» = C1 ON (или C2 ON / снятие STO) в пределах BOTH 1100 + 300 мс, то есть до Q+400 при δ = 0;
  - REL01-e2 (тестировщик): «принят» — подъём до Q+1500, «момент критерием не нормирован».
  - Правило L нормирует моменты **аварийной** реакции, не подъёма; D-Q500 — приоритет одиночной команды, не задержку выхода.
- Окно [Q2, Q2+1] в K3-ACK (`E2-G1-v5-k3` §2) источника не имело. Это ошибка критерия, а не дефект F1. Факт F1 из HANDOFF_v6 (C1 ON на Q+3 и без FBK-10) с нормой не сравнивался.

### Норма (TD-06, ждёт просмотра Вадимом)
Q — скан истечения T_BOTH (вторая кнопка + 1000; при δ — p+δ+1000). Для каждого **принимаемого** жеста BOTH:

| Точка | Ожидание | Статус |
|---|---|---|
| каждый скан [p, Q−1] | нет выхода подъёма: (S) `out_LV_C1` FALSE; (R) `out_HV_C2` FALSE и STO установлен | нормативно (BTN-006, q−1) |
| первый скан выхода подъёма | в [Q, Q+400] | нормативно (TD-06, мера «принят») |
| точный скан в [Q, Q+400] | записать в diagnostic | наблюдение |

Для **отклоняемого** жеста: нет выхода подъёма ни в одном скане до конца наблюдения, не раньше Q+1500.

Обоснование (D-TEAM п.2): та же мера «принят», что в уже принятых тестах REL-PERMIT / REL-01; DIS-HOLD держит [a, u] наблюдением. Энергию не добавляет, защиту не снимает, интерфейс не меняет — задаёт только меру уже требуемого подъёма (E6-Q2 «новым жестом»). Вопрос Вадиму по D-TEAM п.4 не нужен.

## 2. FBK10-K4: BOTH-1 нажат в g−1 и удержан через FBK OFF (READY-D) — тест подтверждён

### Сценарий
- Исходно — как CRITERIA_DELTA_v7 §4.5: (S1) Safe + C1_FBK, (S2) Safe + C2_FBK, (R) R&D + C2_FBK. FBK TRUE в [f, g−1], FALSE с g = f+3000. Кнопки отпущены с ≤ f−2000. Прочие разрешения есть, R0.
- p = g−1: обе кнопки нажаты (BOTH-1, δ = 0), удерживаются до p+1100 (через g и через Q1 = p+1000).
- r — первый скан, когда обе отпущены.
- BOTH-2 в p2 = r+2001, удержание 1100 мс, отпускание в r2.
- BOTH-3 в p3 = r2+2001, удержание 1100 мс.

### Вывод
Тест верен: BOTH-2 — только квитирование, подъём — от BOTH-3.

Цепочка:
1. **Q-V7-04 «Б»:** нажатие, пока причина активна (FBK ON без команды), квитированием не засчитывается; попытка потребляется, подъёма нет. После FBK OFF нужно **новое** квитирование по E6-Q2.
2. **E6-Q2 «А» + п.13 «РЕШЕНО»:** квитирует **нажатие** (скан нажатия), а не уровень. Продолжение того же удержания не становится ни квитированием, ни командой.
3. Удержание BOTH-1 через g — продолжение нажатия в p = g−1. Нового нажатия после g в нём нет. Значит, это не квитирование и не команда (TD-04 нормирует p = g−1 как «не засчитано»).
4. BOTH-2 — первое нажатие после g → квитирует и потребляет попытку (K3-ACK).
5. BOTH-3 после отпускания ≥ 2001 мс от r2 — новый жест → подъём.

### Ожидается

| Что | Окно | Статус / источник |
|---|---|---|
| Подъёма нет | каждый скан [p, p3−1], включая Q1, Q1+1 и Q2 | READY-D (Q-V7-04 «Б», E6-Q2, п.13) |
| SafetyFault TRUE | [f+1, p2−1], в т.ч. в [g, p+1100] при удерживаемой BOTH-1 и в паузе [r, p2−1] | READY-D; NV до символа (A8) |
| SafetyFault FALSE | с [p2, p2+1] до конца трассы | READY-D (п.13 «сразу»); NV до A8 |
| BOTH-3 исполняется | нет подъёма в [p3, Q3−1]; первый подъём ≤ Q3+400 | E6-Q2 «новым жестом»; TD-06 |
| Нет Emergency, энергия и стадия неизменны | [f, p3−1] | Q-V4-02 «не Emergency» |

**Запрещено:**
- подъём в BOTH-1 после g (в т.ч. в Q1 — квалификация «по уровню после снятия причины»);
- подъём в BOTH-2;
- SafetyFault FALSE в [g, p2−1] (засчитано удержание через g как квитирование);
- Emergency из-за FBK-10.

**Границы:**
- p = g−1 — норма (этот пункт);
- p = g — TD-04 (наблюдение статуса, подъём в жесте запрещён);
- p = g+1 — K3-ACK (BOTH-1 квитирует).

### Тестировщику
- Добавить в этот тест проверку SafetyFault TRUE в [g, p2−1] и FALSE с [p2, p2+1] (`sfAround`-аналог; NV до символа A8). Сейчас её нет; `noLift` и `steady` оставить.
- `liftIn` для BOTH-3 — по TD-06 (§1).

ID: MOD-008, WDG-004.
