## Новые вопросы

### Высокий приоритет

**Q-RC-14 (E2/E3; EMG4-03, EMG-004, EMG6-01) — потеря connector после выхода из Safe.**
Исходно: устойчивый R&D (C1 ON) или устойчивый Run (C1, C2 ON, STO снят), всё
исправно, кнопки отпущены. Событие: in_LV_Connector_Interlock или
in_HV_Connector_Interlock → FALSE. Что известно: требование EMG-004 —
«аварийное событие»; в Config вы ответили «Emergency, как в любом состоянии»
(V14-Q19). Но в исходной программе (reference 4495a1f и нынешний код)
connector не взводит аварийную защёлку: в Run он ведёт в ту же защитную цепь
Step4, что раньше крышка и Healthy (LV снимается через 2 с, STO через 7 с), а в
R&D только запрещает новые команды включения. Для крышки и Healthy эту цепь вы
уже заменили (Q-RC-01 → Emergency; Q-RC-02 → спуск). Чего не хватает:
(А) Emergency во всех состояниях после Safe (R&D, Safe→R&D, StartingRun, Run,
спуск Run→R&D, R&D→Safe): защёлка, снятие энергии, выход только зелёной
(Restart) после восстановления connector;
(Б) защитный спуск без защёлки: из Run — как при потере Healthy (STO сразу →
5 с → разряд → C2 OFF → R&D), из R&D — R&D→Safe;
(В) иначе, по состояниям. Различаются ли LV и HV connector?
Рекомендация аналитика — (А): совпадает с текстом EMG-004 и V14-Q19; нужен ваш
ответ, т.к. это меняет исходное поведение (появляется защёлка и Restart).

### Средний приоритет

**Q-RC-15 (E3; STP-H) — потеря LV Healthy во время SS1 нормальной остановки.**
Исходно: устойчивый Run, принят down (зелёная или CMD_RUN_TO_R&D), идёт SS1
(первые 2 с, STO ещё не активирован). Событие: пропадает LV Healthy (PS1).
Известно: потеря HV Healthy в SS1 → немедленный STO и fault HealthyLostDuringSS1
(SPEC §9); LV в устойчивом Run → спуск с немедленным STO (Q-RC-02); LV после STO →
остановка продолжается (Q-RC-09). Чего не хватает: (А) SS1 продолжается 2 с,
дальше обычная остановка, в R&D — цепной R&D→Safe; (Б) как HV — немедленный STO
(с fault HealthyLostDuringSS1 или без?).

**Q-RC-17 (E3/E4/E6; IL-05d) — потеря крышки в прочих спусках.** Исходно и
события по вариантам, в каждом InterLock NC1 или NC2 → FALSE:
(1) прерванный запуск после события abort (STO уже восстановлен, идёт
разряд/выдержка/C2 OFF к R&D);
(2) откат неудачного запуска R&D→Run (watchdog C2_FBK 500 мс / HV Healthy 30 с) —
та же последовательность к R&D;
(3) защитный спуск из Run после потери Healthy (Q-RC-02);
(4) откат неудачного входа в Config (Q-RC-06: разряд → C1/C2 OFF → Safe).
Известно: StartingRun → Emergency (Q-RC-03a); нормальный Run→R&D → продолжается
(b1); выход Config → Emergency (b2). Чего не хватает: для (1)–(3) — продолжать
спуск или Emergency; для (4) — Emergency, как выход Config?
Предложение аналитика: (1)–(3) продолжать (STO уже восстановлен, как b1),
(4) Emergency (как b2).

**Q-RC-18 (E4; CFG-09, PLC-14) — Bypass и кнопки при правиле одновременных команд.**
(a) Исходно устойчивый Safe, крышка открыта, PLC держит inPLC_BypassC1C2 = TRUE
(Config не вошёл). Событие: фронт CMD_SAFE_TO_R&D. Считается ли Bypass
«командой перехода» для правила V14-Q8/Q-RC-04 (ошибка, Safe→R&D не
исполняется) или нет (Safe→R&D исполняется)? Аналогично: в Safe удерживается
CMD_SAFE_TO_R&D и приходит фронт Bypass.
(b) Исходно устойчивый Safe или R&D, активна ошибка одновременных команд PLC.
Событие: оператор делает полный жест BOTH (вверх). Исполнять (ошибка касается
только команд PLC) или блокировать до снятия ошибки (как вход в Config —
Q-RC-05(b))? Зелёная вниз при ошибке PLC — предполагаю, исполняется.

### Низкий приоритет

**Q-RC-16 (E3; STP-G4) — LV Healthy вернулась до прихода в R&D.**
Исходно: устойчивый Run. Событие: LV Healthy пропала → защитный спуск (Q-RC-02);
через 3 с (до C2_FBK OFF) LV Healthy вернулась и держится. Чего не хватает: по
приходу в R&D (А) всё равно цепной R&D→Safe (спуск начат потерей LV); (Б) правила
R&D по текущему значению — LV в норме, остаётся R&D. То же для нормальной
остановки (Q-RC-09) и гонки E2-Q1 при восстановлении до C2_FBK OFF.

**Q-RC-19 (E4/E6; CFG-10) — feedback контактора пропал без команды OFF.**
Исходно: Config (C1, C2 ON, FBK подтверждены), Healthy в Config игнорируется.
Событие: C1_FBK или C2_FBK → FALSE, команда ON сохраняется. Watchdog E6 задан
только на ожидание после команды. Чего не хватает: (А) игнорировать; (Б) откат в
Safe + SafetyFault (как Q-RC-06); (В) Emergency. Если реакция одинакова в R&D и
Run — указать; иначе только Config.

## Противоречия между ответами — проверено, вопросов не требуют

- **E6-Q2 «любая кнопка квитирует и потребляет попытку» ↔ Q-RC-07 «зелёная
  квитирует и спускает»:** Вадим сам назвал Q-RC-07(a) исключением из E6-Q2.
  Не противоречие. Выведено без вопроса (READY-D): квитирование — со скана
  нажатия; зелёная < 500 мс в R&D только квитирует; синяя только квитирует;
  исключение — лишь R&D с SafetyFault (в Safe зелёная спуска не имеет).
- **Q-RC-07 «не определено: снимается ли SafetyFault при спуске по PLC»:**
  E6-Q2 прямо говорит «PLC ошибку не квитирует» ⇒ остаётся до кнопки (WDG-07(b),
  READY-D). Отдельный вопрос не нужен; если Вадим хочет иначе — переоткрыть.
- **Q-RC-04 ↔ остановка по PLC:** удерживаемая CMD_R&D_TO_RUN + фронт
  CMD_RUN_TO_R&D в устойчивом Run → ошибка, Run→R&D по PLC не исполняется
  (PLC-05(c)). Следует буквально из ответа «любые две TRUE»; зелёная, EStop и
  TRIGGER не затронуты. Не вопрос, но **сообщить Вадиму как следствие**: PLC
  должен снимать прежнюю команду до следующей, иначе и спуск отклоняется.
- **Q-RC-04 ↔ abort в переходах:** abort StartingRun/Safe→R&D фронтом при
  удерживаемой исходной команде исполняется (переходы вне правила), но по
  приходу в R&D/Safe две TRUE → ошибка до сброса обеих (PLC-05(e)). Следствие,
  не вопрос.
- **Q-RC-01 ↔ Q-RC-03(b1):** граница — скан принятия down t_a (IL-03 / IL-05b).
- **Q-RC-02 ↔ SPEC §9:** §9 — HV в SS1; Q-RC-02 — устойчивый Run; общий принцип
  «немедленный STO». LV в SS1 не покрыт — Q-RC-15.
- **D-ARCH-POL ↔ SPEC §9 «NOT HV_SourceHealthy»:** SPEC говорит о смысле, не о
  полярности сырого входа — совместимо.
- **Q-ARCH-06 ↔ AGENTS «сохранять исходные действия»:** отступление прямо
  подтверждено Вадимом (Network5/Step2, включая 5-с выдержку после FBK).
  Следствие для WDG-02: Healthy, исправный уже до C1 ON, принимается сразу после
  C1_FBK ON — минимальная выдержка не задана; наблюдение, не вопрос.
