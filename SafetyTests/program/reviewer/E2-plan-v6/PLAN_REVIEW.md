## 1. DIS-HOLD (E2a-RC)

### 1.1 Что подтверждено

- Нетлист E2a-core: `b_Reset_HV_Discharg_Req2` — источник N12/FBAnd6, единственный потребитель N1/FBOr5.OrIn2;
  `b_Reset_LV_Discharge_Req2` — источник N11/FBAnd4, единственный потребитель N1/FBOr1.OrIn2. Удаление обоих Symbols корректно,
  Symbols 65 → 63. Межсетевых wire план не вводит.
- Кнопочный путь: `recRndC_SU` = STATE_SU (Set = GATE_020, Reset = ¬`linkSafeRndScope` = ¬(GATE_001 ∧ `b_Step_RnD`)) — это защёлка
  **принятого** R&D→Run, держится только на StartingRun. Модель: SU в a, запрос HV FALSE в a+1, `out_HV_C2` в a+2 = u.
- Модель x1 (E): Safe→R&D HV не снимает; R&D→Run LV не снимает; Safe→R&D снимает LV в a1+1.
- Модель x1 (A): Emergency в StartingRun на a+49 — запрос HV снят при принятии и снова выдан цепью на входе в S5 (до C2 OFF).
  По критерию DIS-HOLD-HV (e ≥ a+2: повторная выдача по цепи) это допустимо.

### 1.2 R6-1 (существенно) — Network12/FBOr1.OrOut не является «принятием R&D→Run»

N12/FBOr1 = OrIn1 `recRndC_SU` ∨ OrIn2 N12/FBAnd10, где FBAnd10 = `inPLC_RnD_Mode` ∧ `inPLC_RnD_Mode_2` ∧ ¬`in_False_SI2_CH8`.
OrIn2 — это **сырой уровень legacy-кода PLC**. Его не гейтируют ни стадия, ни крышка, ни EOk. В legacy-семантике PLC держит
(1,1) всё время Run. Гейтирование идёт ниже: N12/FBAnd4 = FBAnd1 (`b_Step_RnD`) ∧ FBAnd16 (крышка) ∧ FBDecouple3 (FBOr1).
Поэтому `linkRunUpAccepted` = «принятие ∨ команда PLC», а не принятие. Модель (x1, x2; v5 для сравнения):

| Сценарий | v5 | v6 (`linkRunUpAccepted`) | Критерий |
|---|---|---|---|
| R&D, запрос HV TRUE; крышка открыта; PLC (1,1) — подъём отклонён (C2 не выдан) | запрос TRUE | **FALSE со 2-го скана** | запрещено: «снятие отклонённой попыткой» |
| R&D, запрос HV TRUE; `in_ES_NC_1` FALSE и PLC (1,1) | TRUE | **min 0 за 3 с** | запрещено: Emergency не снимает |
| legacy Run (PLC держит (1,1)), `in_ES_NC_1` FALSE | запрос TRUE с входа в S5, C2 OFF через 1 с | **запрос не выдан ни в одном скане; C2 OFF на 9011 без Discharge** | нарушает Q-V7-01 «Discharge → выдержка → C2 OFF», DIS-HOLD-HV (повторная выдача цепью), EMG-001/EMG-010 |

- Legacy PLC-путь в E2a-RC жив (удаляется только в E4). Это наблюдаемое изменение поведения F1/v5, решением Вадима оно не покрыто.
- t18 этих случаев не содержит: «отклонённый BOTH» проверен только кнопками.
- Требуется (архитектору): источник сброса HV — гейтированное принятие подъёма.
  - Пример, проверенный в модели (x2 `alt`): N1/FBOr5.OrIn2 := существующий Symbol `b_Set_HV_C2_1` (N12/FBAnd4.AndOut — команда C2
    в стадии R&D при закрытой крышке). Для кнопок снятие наступает в a+2 = u, то есть ≤ u+1 (норма). Все три строки таблицы
    проходят: запрос остаётся TRUE, legacy-цепь выдаёт его на S5. Новая SAL-переменная не нужна: SAL-переменных 75, а не 76;
    у Symbol добавляется второй targetUsage.
  - Это не предписание: подходит любой источник, который является принятием, а не уровнем команды.
  - Текст «снятие в [a, a+1]» исправить под выбранный источник.
- Мутация: добавить «сброс от негейтированного уровня команды (N12/FBOr1 / FBAnd10)». Убийцы — строки таблицы (отклонённый PLC-подъём
  при открытой крышке; Emergency из legacy Run).
- Тестировщику: в DIS-HOLD-HV добавить отклонённый legacy-PLC-подъём и Emergency при удерживаемом PLC (1,1) — как варианты уже
  перечисленных критериев. Новых требований здесь нет.

### 1.3 R6-2 (умеренно) — LV: `b_Step12_Set` включает legacy-путь без EOk

`b_Step12_Set` = N2/FBOr1 = `linkSafeAcceptedUp` ∨ N2/FBAnd91 (`inPLC_RnD_Mode` ∧ ¬`inPLC_RnD_Mode_2` ∧ `b_Step1`). FBAnd91 не
гейтирован EOk. Модель x1 (D): Safe, запрос LV TRUE, `in_ES_NC_1` FALSE (Emergency), затем PLC (1,0) — **запрос LV FALSE 2 скана**
(сканы 2–3), потом снова выдан цепью. В v5 он TRUE без перерыва.
- Нарушает TD-01 (подтверждён Вадимом, вопрос 74): «Emergency … его не снимают».
- Корень — давняя legacy-аномалия: грант g2 двигает стадию S1→S12 в Emergency (и в v5). Новое здесь только снятие запроса.
- Требуется: сброс LV — от гейтированного принятия Safe→R&D (например, с EOk), либо через аналитика оформить known FAIL
  «legacy PLC Safe→R&D в Emergency» до E4 с обоснованием. Молча оставлять нельзя.

### 1.4 R6-3 — точка убийц M-E2a-30/31/33

Критерий: [a, u] — наблюдение, норма — FALSE в u+1. В модели u = a+2. Убийца «TRUE в a+2» попадает в интервал наблюдения.
Переформулировать: «TRUE в u+1 (u1+1)». Мутант держит TRUE всегда, поэтому убиваемость не меняется. M-E2a-33: «TRUE в u+1 … a+499».

### 1.5 R6-4 — M-E2a-32 на кандидате E2a-RC

На E2a-RC (без E2b) GATE_001.AndIn5/6 = NC1/NC2. При открытой крышке GATE_004/GATE_012 = FALSE, BOTH не квалифицируется и

не убивает (на полном стеке убивает, x3 `full`). Нужен убийца, достижимый на E2a-RC: **Safe→R&D BOTH при выставленном запросе HV —
запрос остаётся TRUE** (DIS-HOLD-HV: Safe→R&D не снимает). В x3 `full` он убивает. На стеке «только RC» x3 — NV: прототип без E2b
не воспроизводит D-1, поэтому R&D с запросом не достигается. Либо явно перенести прогон M-E2a-32 на стек E2b.

## 4. E2b

### 4.1 B6-1 (существенно) — EMG6-01-BOOT: отложенный выход в Safe без нового Restart

Нетлист: g1 = N3/FBAnd1 = `in_Safety_Run` ∧ `b_EStop_Ok` ∧ нет стадий ∧ FBAnd2. Фронта Restart в g1 нет: EOk защёлкивает FBEstop1 по Restart.

срабатывает сам. Модель x4 (C1_FBK / C2_FBK / оба):

| FBK OFF в | Ожидание (EMG6-01-BOOT) | v6 |
|---|---|---|
| r+1 | Emergency до нового Restart | **S1/SAFE на g+2** |
| r+2000 | то же | **S1/SAFE на g+2** |
| никогда | Emergency | Emergency |

- Это прямо запрещено критерием: «Safe без нового Restart после g», «g ≥ r+1 → нет отложенного исполнения Restart».
- t18 проверяет только «FBK OFF + новый Restart», поэтому дефект не виден.
- Требуется (архитектору): выход по g1 с FBK OFF именно в момент Restart (как G10_EXIT: фронт/отпускание `in_Reset_PB`, `recRndC_PrevG`).
  Либо иной механизм, исключающий исполнение после g без нового Restart. Добавить мутацию с убийцей «FBK OFF в r+1 / r+2000 без
  нового Restart → Safe». Мутации M-E2b-37/38/39 остаются.
- Тестировщику: в EMG6-01-BOOT обязательно g = r+1 и g = r+2000 без нового Restart (критерий уже требует).
