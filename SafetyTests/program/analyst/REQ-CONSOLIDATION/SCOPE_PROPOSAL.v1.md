# REQ-CONSOLIDATION — предложение по перечню ID (для ведущего)

Срез / роль / дата: REQ-CONSOLIDATION / v2-analyst / 2026-10-21.
Это предложение; SOFTWARE_ACCEPTANCE_SCOPE.md, SPEC §§19–20 и TRACE_MATRIX.json
правит ведущий. Ни один ID не удаляется: ID сохраняются при уточнениях
(SPEC §19). «Утратил смысл» = часть формулировки неприменима, предложена замена.

закрытие одного ID потребует слишком разнородных сценариев; рекомендую новые ID.

| Этап | ID |

| E4 команды PLC / Config / heartbeat | PLC-001…006, CFG-001…005, HB-001, MOD-003, MOD-004, MOD-007, CVR-004 (PLC-маршруты), EMG-006 (PLC не снимает), EMG-001 (PLC-источник), group/alias/mapping по V14-Q2 |
| E5 SafetyFault | WDG-004, BTN-001/007 (квитирование), статус ошибки в PLC (Q-RC-13) |

Зависимости порядка: E3 использует WDG-003 (C2 OFF stuck → Emergency) — если
E6 позже, STP-C в E3 оставить RED/NV с пометкой; E5 (квитирование) нужен для
приёмки E6-откатов; E2 должен заложить Config в механизм статусов, иначе E4
повторно перестроит присвоение статусов.

## 4. Сопутствующие правки статуса (для ведущего)

- TRACE_MATRIX `frozen.E4`: ответы V14-Q8…Q14/Q20 и пересмотр V14-Q2 дают
  материал для E4; размораживать или нет — решение ведущего/Вадима
  (AGENTS.md ещё говорит «на полном пересмотре»).
- TRACE_MATRIX EMG-001/EMG-005 `criteria`: ссылка на E1-f1-MU06 C01–C03
  «in_False=TRUE» — C01/C02 вне объёма по Q-MU06-01; оставить только C03.
- SCENARIO_DECISIONS, блок «E4 — команды из контроллера»: пометить как
  заменённый ответами V14-Q8…Q14 (правка ведущего/аналитика по поручению).
- SPEC §2/§4/§14 (Config, one-hot), §5 п7/п11 и §6 (Safe→R&D при открытой
  крышке), §6 п3 (C3/BMS), §10 (TransitionFault при discharge timeout) —
  устарели в указанных частях.
