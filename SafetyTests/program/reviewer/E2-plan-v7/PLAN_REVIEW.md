## 4. N7-1 (существенно, E2d) — гейт ¬C2_FBK уровнем на N12/FBAnd10 обрывает штатный legacy-подъём (FBK10-PLC-REG = FAIL)

Сравнение поскан «с гейтом v7.1 против без гейта» (`x6.out.txt`; без гейта = три входа v7.1 деактивированы, прочее то же):

| Сценарий | Без гейта | С гейтом v7.1 |
|---|---|---|
| Safe, PLC (1,0) удерживается | S12 +2, C1 +4, R&D +603 | **то же** (FBAnd91.AndIn5/6 — PASS) |
| R&D, PLC (1,1) удерживается 30 с | C2 +3, FBK +4, Run (S3) +603, STO снят +604 | C2 +3, FBK +4, **`b_Set_HV_C2_1` падает на +6; R&D до конца 30 с, C2 ON, STO не снят** |
| То же с запросом HV TRUE | запрос FALSE +3, Run +603 | запрос FALSE +3, **R&D с C2 ON 30 с, запрос HV FALSE** |

Механизм: в legacy R&D→Run нет защёлки SU. Команда держится уровнем FBAnd10 → FBOr1 → FBAnd4. Собственный C2_FBK ON (скан +4)
снимает FBAnd10, FBAnd4 падает, WIN_C2/FBTon3 сбрасываются, подтверждение Run не наступает. C2 при этом защёлкнут
(FBOr18 → HvSetPermit → RS) и остаётся включённым.

Последствия:
- штатный legacy-подъём R&D→Run больше не работает. Это фактически вариант (б) «отключить legacy-путь» — изменение интерфейса PLC,
  по D-TEAM п.4 нужен вопрос Вадиму. Решение ведущего (а) это не разрешало;
- хуже отключения: остаётся застрявшее состояние «стадия R&D, HV включён, запрос разряда снят, Run не будет».
  В нём R&D→Safe зелёной не исполняется (см. N7-2, `x10`). Выход — только через Emergency;
- нарушен критерий аналитика FBK10-PLC-REG (2): «собственный FBK ON после выданной команды не снимает C2, не прерывает запуск».
- t22 этого не видит: позитивный контроль там есть только для Safe (1,0), а R&D-строка проверяет лишь «FBK ON без команды».

Требуется (архитектору):
- гейт R&D→Run по FBK-10 должен проверять «FBK ON **без команды**», а не сырой уровень FBK. Примеры — не предписание:
  - `¬C2_FBK ∨ out_HV_C2` (+1 FB OR);
  - проверка только в скане принятия / через память.
  Проверить порядок исполнения: out_HV_C2 должен быть TRUE раньше, чем FBK станет ON (в модели — на скан раньше).
- для N2/FBAnd91.AndIn5/6 изменение не требуется: g2 — грант на 2 скана, стадия S12 защёлкнута, C1 идёт от стадии (x6 PASS).
  Тот же довод записать в план.
- добавить в t22 позитивный контроль R&D (1,1) без FBK → Run, FBK = команда + 1 скан, x ∈ {1, 250, 499}.
- мутации:
  - M-E2d-14 сохранить (убийца — FBK ON без команды);
  - добавить мутант «гейт по сырому уровню FBK» (вариант v7.1). Убийца — FBK10-PLC-REG (2).

Тестировщику: FBK10-PLC-REG (1) и (2) обязательны. На текущем плане (2) обязана дать FAIL; скрывать или ослаблять нельзя.

### V77-3. Довод «AND с нажатием не нужен» — верен

Довод того же вида, что для M-E2b-47/48:
- терм фазы ставит STATE_PF без нажатия только пока RELEASE.TonOut FALSE, то есть пока кнопки отпущены меньше фильтра;
- любая попытка в этом интервале и так недействительна (BTN-001; проверено: rel+1999 → отказ);
- при TonOut TRUE доминирующий Reset держит STATE_PF = 0;
- в скане нажатия Set (фаза) действует и с AND, и без него.

Значит, вариант с AND и вариант без AND дают одинаковые исходы. Q-REL-AFTER-PERMIT при этом сохраняется: отсчёт идёт только по кнопкам, сброс — по тому же TonOut (сценарии V77-2).

### V77-4. Перенос в E6 — честный, но обоснование и `carryOver` уточнить (V77-A)

Слова «StartingRun ≈ 600 мс, короче очистки» верны только для обычного случая. При `in_HV_Faulty_FBK` StartingRun держится неограниченно (тестовый сценарий «HV Faulty holding StartingRun»), и BOTH после полной очистки в SU **начать можно**.

Почему дефект в E2 всё равно недостижим: выхода SU → R&D в E2 нет.
- Abort зелёной (V14-Q12) не реализован, это E3 — на модели «StartingRun + зелёная после 2,1 с → Run».
- Откат окна — E6.
- CMD_RUN_TO_R&D — E4, к тому же при нажатой кнопке игнорируется (V14-Q14).
- Жест, начатый в SU, кончается в Run (там BOTH игнорируется) или в Emergency (V77-2: identical).

Мутант с термом SU в E2 был бы неубиваем — с переносом согласен.

**V77-A (архитектор, текст):**
- обоснование в PLAN.md поправить так: «SU может длиться неограниченно (HV Faulty), но в E2 нет перехода SU→R&D»;
- `carryOver`: добавить `recRndC_SU` в GATE_PHASE при появлении **первого** пути SU→R&D — abort зелёной (E3, V14-Q12), CMD_RUN_TO_R&D (E4) или откат окна (E6). Привязка только к E6 может опоздать, если E3 появится раньше;
- там же добавить общий пункт: фазы, запускаемые новыми командами E4 (например, R&D→Safe от PLC при медленном C1_FBK), проверить по MOD-004 по форме XPH-01.
