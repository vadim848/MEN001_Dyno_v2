# Независимое ревью плана03C clock

2026-10-19. Проверены ITERATION_03C_TIMER_CLOCK_PLAN.md и обновлённый
ITERATION_03B_PHYSICAL_PLAN.md. Это ревью технического плана; runtime, SAL
и тесты ревьюер не менял, выполнения ещё не подтверждает.

## Вердикт

План03C принят к реализации в явно ограниченной fixed-scan software model.
Существенных незакрытых замечаний к плану нет. Это не автоматическое разрешение
писать SAL03B: сначала реализация/проверка03C, causal helper trace и generated
netlist/order map03B, затем отдельное ревью.

## Проверенная хронология

Единый observed-edge договор устраняет смешение first observed sample age0
и начисленного за него полного dt. TON и EStop off-delay исправляются общим
правилом для всех блоков, не именованной special-case250. Параметры SAL и
SGVL не меняются. Это коррекция модели времени и её явное допущение,
не доказательство происхождения времени native firmware.

При loss sample t0 offElapsed0. При фиксированном шаге1мс delayed после
helper остаётся TRUE до249 и становится FALSE на250. Snapshot до helper
на250 ещё TRUE от249, на251 уже FALSE от250: inclusive250 получается
без параметра251. На шагах2/5/10 тот же вывод верен, потому что250 кратно
шагу и событие отсчитывается от зарегистрированного sample первой кнопки.
Nearest-grid проверки корректно заменяют непредставимые249/251 на этих сетках.

Scheduler first scan фиксирует t0, затем advance(delta−dt), set second,
scan(dt) фиксирует точную delta. Отдельное автоматическое сравнение timestamps
не позволяет лишний scan назвать прежней границей. Causal StartG/StartB→helper
проверка обязательна: одинаковая арифметика ручного готового delayed output
не докажет правильного реального порядка графа.

Произвольный jump249→251 может принять251 через старый snapshotTRUE;
план прямо сохраняет этот предел и не заявляет arbitrary-step/native exactness.
В fixed-scan области противоречия включительной границе нет. Если реализация
или отчёт выйдут за эту область, утверждение придётся пересматривать.

## Условия приёмки реализации

- Все configured TON и EStop100/250 получают независимые edge/threshold/
  reset/rehold/restore traces на fixed1/2/5/10; startup не создаёт delayedTRUE.
- Clock tests различают прежнее начисление первого dt и новую модель;
  положительные результаты не должны быть только повторением реализации.
- Historical fixtures и качественные oracle сохранены. Любое изменение
  scan counts имеет перевод old convention→new observed timestamps в отчёте.
  Нельзя добавлять произвольные ожидания до PASS или скрывать новые FAIL.
- Сравнение pre/post использует неизменный SAL/SGVL SHA и перечисляет всю
  функциональную дельту, отделяя clock correction от исправления логики.
- Actual SAL03A проверяется новым scheduler, прототип не подменяет source.
  Structural B1 audit, mutations, полный пакет и независимое ревью обязательны.

03C само по себе не исправляет recognizer, не закрывает оставшиеся41ID и не
доказывает physical/native validation. Эти границы в плане сформулированы ясно.
