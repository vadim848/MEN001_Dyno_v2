## Совпадает с действующими решениями
- Состояния Safe / R&D / Run(=Armed в PLC) / Emergency; R&D = LV (PS1+батарея+BMS), HV off.
- Жесты: dual press = UP, короткая зелёная = DOWN, синяя одна = открыть крышку (Safe, R&D); отказ в Run/Emergency.
- UP только при закрытой крышке (у нас InterLock NC1∧NC2); в Emergency крышка заперта.
- Emergency защёлкивается; восстановление физическое; PLC не снимает Emergency и не открывает крышку.
- PLC emergency (`in_Estop_PLC`) и Mentee driver (`in_Mentee_EStop`) — уже есть входы.

## Новое / расхождения (кандидаты в вопросы аналитика)
1. **PLC-команды:** 5 индивидуально адресуемых команд + статус `STS_COVER_LOCKED` вместо текущего 2-битного уровня (`inPLC_RnD_Mode`, `_2`). Новые сигналы PLC↔TwinSAFE = изменение process image группы → сейчас запрещено AGENTS.md (group/target). Нужно разрешение или решение уложиться в существующие сигналы.
2. **Скриншот PLC противоречив сам себе:** таблица «Armed→RnD = Bit1 0, Bit2 1», код CASE пишет (TRUE, FALSE). Код читается как уровень целевого состояния (00 Safe, 10 RnD, 11 Run); тогда idle-код 00 = постоянный запрос Safe, а при 11→10 возможен промежуточный 01/00. Это известный дефект «декодирование по уровню».
3. **Run→R&D: подтверждённые нулевая скорость и нулевой ток до снятия HV** (§5, §8 #1, §9). В SAL нет таких входов. Отношение к утверждённой SS1 2с→STO→coast 5с→разряд→C2 OFF не определено.
4. **Heartbeat PLC–TwinSAFE** (§7): потеря → Emergency, таймаут — PLACEHOLDER. Входа нет; значение не задано.
5. **Emergency→Safe:** «engage/dis-engage E-Stop» даже если аварию вызвал PLC/driver/watchdog. Сверить с текущим Restart/ErrAck и EMG-006.
6. **Внутреннее противоречие документа:** §5/§8 (v1.4) — PLC может запросить UP; §6 шаг 3 — «Both UP-steps are physical only» (остаток v1.2). Применяется ли запрет только после аварийного восстановления?
7. **«Closed + locked»:** документ требует закрыто И заперто; решение Вадима — энергия по InterLock NC1∧NC2, отдельный lock-feedback gate не нужен. Подтвердить, что NC1∧NC2 = «closed + locked».
8. **PS2 HEALTH игнорируется в R&D** — проверить текущий код.
9. **`inPLC_BypassC1C2`** в документе отсутствует; связан с найденным Safe+Armed путём (Bypass TRUE). Судьба сигнала не определена.
