## 1. Unlock и DoorMonitor (Q-T3-2)

**UNL-04 — исправление (READY; Q-ARCH-04 «А», Q-ARCH-10 «А»; CVR-001/002/003).** В исходном состоянии вместо
«Door TRUE/FALSE» читать **`in_Door_Monitor` TRUE** (устойчиво с момента входа в состояние). Остальное без изменений:
- открытая крышка = NC1, NC2 или оба FALSE; контроль — закрытая;
- Safe и R&D;
- s+499 FALSE, к s+501 TRUE (s+500 — наблюдение), удержание, отпускание → FALSE;
- зелёная снимает Unlock.
Источник исправления: Q-ARCH-04/10 касаются только InterLock NC (F1 guard в `RndPhysicalCompact/GATE_001`). Door
в Unlock сохраняет роль (reference FBAnd8 → FBRs1.Reset; D-DOOR-INTERLOCK; SPEC §5 п.6, п.9; CVR-004, CVR-006).

**UNL-05 — новый (READY; reference 4495a1f Network2/FBAnd8+FBRs1; D-DOOR-INTERLOCK; SPEC §5 п.9; Q-ARCH-04 «как в
reference», Q-ARCH-10 «как в Safe»; CVR-001, CVR-004, CVR-006).**
- Исходно:
  - устойчивый Safe — вариант S, или устойчивый R&D — вариант R;
  - `in_Door_Monitor` FALSE устойчиво (≥ 2000 мс до s);
  - InterLock: (a) NC1 FALSE, (b) NC2 FALSE, (c) оба FALSE, (d) оба TRUE — контроль «закрыто по NC»;
  - EStop OK, `in_Estop_PLC` FALSE, кнопки отпущены ≥ 2000 мс, нет Emergency и SafetyFault.
- Событие: синяя нажата в s и удерживается 1000 мс; затем отпущена. Вариант: удерживается 3000 мс.
- Ожидается в каждом скане от s до конца наблюдения (≥ 2000 мс после отпускания):
  - `out_Door_Unlock_Solonoeid` FALSE;
  - состояние неизменно (Safe или R&D);
  - нет Emergency, fault и SafetyFault (CVR-003);
  - нет перехода Safe→R&D или R&D→Run от одиночной синей.
- Запрещено: Unlock TRUE хотя бы 1 скан.
- Границы:
  - Door TRUE с s−1 (устойчиво) → UNL-04: Unlock TRUE к s+501;
  - Door FALSE только в скане s → наблюдение.
- Падение Door во время выданного Unlock, **только Safe**. Исходно UNL-04 Safe (Door TRUE, синяя квалифицирована,
  Unlock TRUE), Door FALSE в d ≥ s+600 при удерживаемой синей:
  - Unlock FALSE не позже d+1 (reference: FBAnd8 order 100 после FBRs1 order 96, поэтому d+1);
  - Unlock FALSE в d — допустимо (наблюдение);
  - d−1 — Unlock TRUE.
  - Вариант NC FALSE (крышка уже открыта по NC) — то же.
- BLOCKED Q-T3-2b (только наблюдение):
  - Door снова TRUE при всё ещё удерживаемой синей (Safe);
  - падение Door во время Unlock в R&D.
- Аварийные сочетания:
  - Door FALSE и `in_Estop_PLC` TRUE в одном скане → EMGREF, Unlock FALSE;
  - Door FALSE и зелёная → Unlock FALSE.
  Оба случая — без нового повышения энергии.
- Мутации, которые должен убивать UNL-05:
  - удаление `N2/FBAnd8.AndIn1` (Door из сброса Safe);
  - удаление Door из `N12/FBAnd2` (выдача в R&D).
  Для этого обязательны варианты (a)–(c): на кандидате guard по NC снят, и FALSE обеспечивает только Door.
  Вариант (d) один мутацию Door не отличает, если остаётся NC guard. Имена блоков — справка по canonical F1,
  итоговые имена выбирает архитектор.

## 2. Правило L в фазах уже идущего снижения энергии (Q-T3-1)

**EMG-RD-L — дополнение к §0.1 v4, заменяет допущение тестировщика A11 (READY-D; дизъюнкция до ответа Q-T3-1).**
Область:
- фазы, где без события продолжающаяся нормативная последовательность сама переводит выход o (Del: STO_DR1/2,
  `out_HV_Discharge_Request`, `out_HV_C2`, `out_LV_C1`) в аварийное целевое значение;
- это Run→R&D (STP-A/B: SS1, выбег, выдержка разряда, ожидание C2_FBK OFF), abort StartingRun (STP-E/I), откат
  WDG-03, защитный спуск STP-G/H, R&D→Safe (MOD5-01), откат Config (E4).
Событие: `in_Estop_PLC` (L2) или иная причина (L1) в e.

Обозначения:
- W_N(o) = [q_N(o), q_N(o)+1] — **нормативное** окно момента o по критерию этой фазы без события;
  - для Run→R&D: STO q_N = t_a+2000, Discharge q_N = t_s+5000, C2 OFF q_N = t_d+T_DIS;
  - t_s и t_d — фактические сканы STO и Discharge **той же** трассы с событием;
- q_R(o) = τ_Run(o) — момент того же выхода при `in_Estop_PLC` в устойчивом Run (L2/L3).
- **Запрещено брать q_N из наблюдаемой no-event трассы реализации.** Наблюдаемая трасса — только диагностика:
  нормальная остановка canonical дефектна (E3).

Нормативно для выхода o, не достигшего цели до e:
1. Если q_N(o) ≥ e+q_R(o): буквальный L2/L1 без изменений, Del в [e+q_R, e+q_R+1].
2. Если q_N(o) < e+q_R(o): **дизъюнкция**. Нормативна сама дизъюнкция, выпавшая ветка — `t.diagnostic`.
   - (А) τ(o) ∈ W_N(o): шаг нормальной последовательности не отложен;
   - (Б) τ(o) ∈ [e+q_R(o), e+q_R(o)+1]: момент аварийной цепи.
   - Всё остальное — FAIL. В частности:
     - τ в (q_N+1, e+q_R) — нормальный шаг отложен, но не до момента цепи. Неверно при обоих ответах;
     - τ < min(q_N, e+q_R) — укороченная выдержка, v2-questions Т1 п.3;
     - τ = never.
   - Выбор ветки во всей трассе один: при (А) для всех таких o той же трассы — (А), при (Б) — (Б).
     Смешение веток — FAIL. Ответы А и Б задают одно правило на всю реакцию.
3. Выходы, которые нормальная последовательность не меняет (C3/BMS OFF, LV discharge; C1 OFF в Run→R&D) —
   L1/L2 без изменений.
4. Выход уже в цели до e («n/a»): остаётся в цели в каждом скане ≥ e. Для STO это EMGREF(2): нет снятия STO.
5. L4: статус Emergency не позже первого изменения выхода по ветке (Б) или по аварийным выходам из п.3. Изменения
   в пределах W_N (ветка А) в L4 не учитываются.
6. Без изменений: конечное состояние, защёлка, EMGREF(1)(2), Restart → только Safe.

Границы: e = t_a−1 — устойчивый Run (L3); e = t_a+1 — EMG-RD-L; e = t_a — наблюдение. Свип e по фазе: t_a+1,
t_a+1999, t_a+2001, t_s+4999, t_d+T_DIS−1, а также в ожидании C2_FBK OFF.
Аварийные сочетания:
- событие e в скане q_N(STO) или q_N(Discharge) — наблюдение;
- e в одном скане с потерей Healthy в SS1 (STP-D) — Emergency приоритетнее, моменты по EMG-RD-L.

После ответа Вадима на Q-T3-1 дизъюнкция сужается до одной ветки: (А) → п.2(А), (Б) → п.2(Б). Ответ (В) или иной
пересматривается аналитиком.
Статус: READY-D (дизъюнкция). Выбор ветки — BLOCKED Q-T3-1.
