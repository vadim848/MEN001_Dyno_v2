Это объясняет происхождение latch, но новое требование явно меняет старое
поведение: отпускание синей обязано снять команду, зелёная запрещает unlock.
Контрпример ACC-C01-S воспроизводит сохранение выхода после отпускания.

Итерация закрывает только удержание/исключение зелёной на конечной команде и
очистку старого разрешения при прерывании. Это НЕ завершение recognizer,
блокировки переходов, аварийной цепочки или разрешения доступа по энергии.
В частности, EMG-007 и оставшиеся CVR-004/006 остаются отдельными задачами.
Таймеры и их существующие значения не менять. Hardware/aliases/global
parameters не исследовать и не менять. Новую обратную связь не придумывать.

## Приёмка фактического SAL

Редактор добавляет исполняемые проверки реального SAL и структурные assertions,
не меняет историческую fixture и предварительные требования времени кнопок.

- Safe: синяя квалифицирована существующей ветвью → output TRUE; отпущена
  → FALSE в первом моделируемом скане, latch FALSE; повторная синяя до полного
  существующего TON → FALSE, после полного TON → TRUE.
- Та же последовательность R&D, без предположения, что её Set автоматически
  совпадает с Safe; использовать фактические producers Network12.
- При квалифицированной синей появление зелёной снимает output/latch;
  после отпускания зелёной прежнее разрешение не воскресает. Новая квалификация
  может быть проверена только по фактическому producer, не выдуманному таймеру.
- Одновременные Set и !blue / green: reset dominance, output FALSE.
- Таблица 8 сочетаний latch/blue/green на конечном AND даёт ровно
  latch && blue && !green; это компонентная проверка, не признание безопасной энергии.
- Проверка sole writer, GUID uniqueness, XML well-formedness, orders1–206,
  unchanged timer inventory и alias/global-parameter sections.
- ACC-C01-S должен стать PASS. ACC-C02-X должен не допускать unlock при chord
  (зелёная TRUE), но его PASS не объявляет исправленным весь upward permission.
- Полный npm run check:software; исторические и harness без новых регрессий.
  Остальные реальные FAIL не скрывать и не переводить в skip/NV для приёмки.

Существующие candidate checks выбирают явные списки блоков. После смены writer
их cover selection обязана включать новый output AND и нужные входы, иначе
проверялся бы исчезнувший subgraph. Такое обновление привязки документировать,
сами ожидаемые результаты не ослаблять. Новый набор обязан также исполнять
реальную полную разрешённую цепочку (исключение Network4 явно сохранять),
чтобы компонентная таблица не стала единственным доказательством.

## Ограничения и передача на ревью

Частичный SalRuntime не моделирует весь group lifecycle/Network4; фиксировать
эти ограничения и шаг сканирования. Первый скан означает модельный скан,
не физическую гарантию времени. Полный recognizer/rearm и emergency closure
не входят в эту итерацию. Не объявлять запрос перехода фактической энергией.
Встроенный CRC не пересчитывать выдуманным алгоритмом и не выдавать за актуальный:
после XML diff он требует отдельной native regeneration, Verify/Build/CRC вне scope.
Изменение .sal.diagram допустимо только если требуется согласованность вида и
редактор умеет сохранить формат; отсутствие native проверки явно в отчёте.
Независимый reviewer проверяет отсутствие обхода gate, восстановление старого
latch, полноту тестовой выборки, сохранение входных конфигураций/таймеров.

Разрешённые файлы редактора: рабочий SAL, тесты и привязки текущего SAL в
SafetyTests, воспроизводимый отчёт результатов. Reference и historical fixture
только читать. Существенный новый дефект или повторная неудача → архитектору.
