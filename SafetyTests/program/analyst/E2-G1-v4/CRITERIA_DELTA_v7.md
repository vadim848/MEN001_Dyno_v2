### Разбор источников

**v5 п.4.** «Выход уже в цели до e: остаётся в цели в каждом скане ≥ e».
- Буквально относится к выходу, который находится в цели в скане e−1.
- Импульс, снятый до e, в скане e−1 вне цели. П.4 к нему буквально не применяется.
- П.2(А) тоже неприменим: τ ≥ e не может лежать в прошедшем W_N (ревьюер прав).

**Q-T3-1 «А».** «Каждый выход: момент = min(нормальный, цепь)».
- Шаг уже выполнен в нормальный момент, то есть min уже достигнут.
- Обязывает ли авария повторить запрос — ответ не говорит.
- Перечень «авария добавляет свои действия» — защёлка, LV/C3/BMS. HV discharge в нём не назван.
- Но HV discharge входит в общую цепь Q-ARCH-01 («далее ветка STO/HV discharge»). Значит, возможны оба прочтения: «шаг сделан, повтор не нужен» и «цепь выдаёт свой запрос».

**Reference 4495a1f (чтение SAL, `git show`).**
- `b_Set_HV_Discharge_Request` → Network1/FBOr6 → FBRs7.Set.
- Reset FBRs7 ← FBOr5 ← `b_Reset_HV_Discharg_Req`. Пишется только в Network5 — исходный power-on старт, удаляемый по R1 (Q-ARCH-06/Q-64).
- Итог: в reference запрос разряда — уровень. Он держится от выдачи до следующего старта, импульса нет.
- Проба ревьюера (`repro/dis-latch-probe.out`): в Emergency из Run TRUE с +7008 до конца защёлки (+10099).
- Ситуация «шаг выполнен и вышел из цели» в reference не возникает вообще. Reference не даёт реакции на неё.
- Момент снятия запроса в новом Run→R&D решениями не задан. STP-A нормирует только момент выдачи (t_s+5000), R1 удаляет место сброса.

**Уточнение тестировщика** (повтор ровно в [e+7008, e+7009]) — одно из возможных прочтений. Нормативным oracle его делать нельзя (AGENTS.md).

- провал FBK в скане w → наблюдение.

### 4.5 FBK-10 — FBK ON без команды ON в устойчивом Safe/R&D (MOD-008, WDG-004; Q-V4-02 «В»)

Источник: SCENARIO_DECISIONS Q-V4-02 «В» (ddee4552…). Текст записи:
- SafetyFault (общий бит Fault для PLC) и запрет подъёма, пока FBK не станет OFF;
- квитирование по E6-Q2 не снимает запрет, пока FBK ON;
- не Emergency;
- FBK ON в окне 500 мс после команды OFF — это E6-Q1, сюда не относится.

**Сверка букв.** В исходной формулировке вопроса (E2-G1-v2-questions/QUESTIONS.md) буквы были другими: (В) = Emergency, (Б) = SafetyFault. Записанный текст ответа однозначно описывает SafetyFault + запрет подъёма, «не Emergency». Критерий построен по тексту записи, не по букве. Ведущему: подтвердить, что Вадиму задавалась новая редакция вопроса. На исполнение не влияет.

Исходно:
- **(S1)** устойчивый Safe:
  - команды C1, C2 OFF; C1_FBK, C2_FBK OFF;
  - кнопки отпущены ≥ 2000 мс;
  - нет SafetyFault/PLC-ошибки; R0.
  - Событие C1_FBK.
- **(S2)** то же, событие C2_FBK.
- **(R)** устойчивый R&D (после MOD1-01 или после завершённого Run→R&D): C1 ON, команда C2 OFF, C2_FBK OFF.

Событие: соответствующий FBK TRUE в f без команды ON, удерживается до f+3000, затем FALSE. Вариант: 1 скан (FBK ON только в f).

Ожидается (READY-D: момент — конвенция q/q+1, фильтр не задан):
- SafetyFault TRUE и общий бит Fault для PLC TRUE не позже f+1.
  - SafetyFault: проверка NV до символа (A8).
  - Бит Fault PLC — E4/E5.
- Состояние неизменно (Safe или R&D), энергия не меняется. Нет:
  - Emergency и защёлки;
  - снятия C1 в R&D;
  - изменений STO/SS1/Discharge;
  - перехода.
- Запрет подъёма в каждом скане от f до первого скана FBK OFF и далее до квитирования. Не исполняются (C1/C2 ON не выдаются, STO не снимается):
  - BOTH (Safe→R&D, R&D→Run);
  - CMD_SAFE_TO_R&D, CMD_R&D_TO_RUN;
  - вход в Config/Bypass (READY-D: Config — подъём энергии).
- Спуск не блокируется (Q-RC-07): в (R) зелёная ≥ 500 мс → R&D→Safe исполняется.

Квитирование (E6-Q2: любая кнопка, затем обе отпущены 2 с):
- **(k1)** квитирование, пока FBK ON → запрет сохраняется: BOTH после паузы не исполняется, пока FBK ON. READY.
- **(k2)** FBK OFF → квитирование → BOTH 1 с → подъём исполняется при прочих разрешениях. READY.
- **(k3)** FBK OFF без квитирования → подъём запрещён (SafetyFault активна, WDG-06). READY.
- **(k4)** квитирование при FBK ON, затем FBK OFF без нового квитирования: разрешён ли подъём и гасла ли SafetyFault в k1 — **BLOCKED Q-V7-04** (наблюдение).

Границы:
- FBK-10 действует только после установления устойчивого состояния: R&D объявлен по C2_FBK OFF, Safe — по C1_FBK OFF. FBK ON в пределах 500 мс от команды OFF до объявления состояния — E6-Q1/WDG-05, не FBK-10.
- f = скан объявления устойчивого состояния — наблюдение.
- FBK ON в f одновременно с квалифицированным BOTH: исполнение подъёма в f — наблюдение, в f+1 и далее — FAIL.
- 1 скан FBK ON: SafetyFault выставляется (READY-D, фильтра нет). Запрет снимается после FBK OFF + квитирование.

Аварийные сочетания:
- FBK-10 + EStop/`in_Estop_PLC` → Emergency по причине EStop (EMGREF).
  - Restart требует FBK OFF (SPEC §12, без изменений).
  - SafetyFault после Restart — наблюдение.
- FBK-10 + потеря LV в R&D → HLT-01 (цепной R&D→Safe) не блокируется.

Вне FBK-10 (решением не задано, наблюдение): FBK ON без команды в Run, Config, Emergency, переходах.

Запрещено:
- Emergency из-за FBK-10;
- подъём при FBK ON;
- снятие запрета квитированием при FBK ON;
- изменение энергии или состояния из-за FBK-10.

Мутанты (C5):
- (xiii) удалить условие «FBK OFF» из разрешения подъёма;
- (xiv) квитирование снимает запрет при FBK ON;
- (xv) FBK-10 → Emergency.

Этапы:
- запрет подъёма (MOD-008) — E2d (release-permit; v4-пометку «в REL-PERMIT не использовать» снять) и E5;
- SafetyFault-причина и бит Fault — E5 (NV до символа);
- квитирование k1–k3 — E6 (E6-Q2).
