## RUN-CONF — критерии

Обозначения: u — скан принятия R&D→Run (команда C2 ON, снятие STO); t_f — первый скан C2_FBK ON
(≤ u+500); h — первый скан HV в норме (сырое `in_HV_Faulty_FBK` FALSE) при C2_FBK ON;
k = первый скан, где C2_FBK ON ∧ HV норма (k ≥ t_f). Время в мс = скан 1 мс стенда. Входы
после k устойчивы, если не сказано иное. Run = STS_RUN / стадия Run.

Исходное состояние: устойчивый R&D (C1 ON, C1_FBK ON, LV норма, STO активен, C2 OFF), крышка
закрыта (NC1/NC2 TRUE), EStop OK, нет SafetyFault/PLC-ошибки, кнопки отпущены ≥2 с,
`in_Safety_Run` TRUE; запуск — BOTH-жест 1 с (или PLC-команда — E4, не здесь).

### RC-1 (READY) — нет Run без обоих условий
- (a) C2_FBK OFF, HV норма, до u+499 — Run нет ни в одном скане; дальше — WDG-03 (откат).
- (b) C2_FBK ON с u+1, HV Faulty TRUE до u+3000 — Run нет ни в одном скане < k.
- Общее: Run нет ни в одном скане < k. Источник: Q-ARCH-09 (два обязательных условия), MOD-002, SPEC §7 п.5.

### RC-2 (READY) — нет Run раньше 0,1 с от команды
- Run нет ни в одном скане ≤ u+99 (при любом k). Источник: Q-ARCH-09 «0,1 с» — во всех трёх
  трактовках Run не раньше u+100 (а: ≥u+100; б/в: ≥k+100 ≥ u+101). Скан u+100 — наблюдение (семантика TON).

### RC-3 (READY) — Run наступает
- При устойчивых C2_FBK ON и HV норма с k: Run есть на k+101 и далее (пока нет события спуска).
  Источник: Q-ARCH-09; во всех трёх трактовках Run ≤ k+100.

### RC-4 (READY) — не требуются 5 с и STO FBK
- `in_STO_DR*_FBK` закреплены «STO активен» — RC-3 выполняется (Run на k+101); Run не ждёт
  k+5000. Запрещено требовать выдержку 5 с и STO FBK. Источник: Q-ARCH-09.

### RC-5 (BLOCKED Q-RC-RUNCONF-01) — точный момент Run
- (а): Run в скане max(u+100, k) (±1 по правилу L — наблюдение); граница: нет Run на max(u+100,k)−1.
- (б)/(в): нет Run на k+99, Run на k+101 (k+100 — наблюдение).
- Сценарии разделения: (i) t_f=u+1, h ≤ u (k=u+1); (ii) t_f=u+30, h ≤ u (k=u+30; вопрос архитектора);
  (iii) t_f=u+400; (iv) h=u+3000 (k ≫ u+100: (а) Run ≈k, (б)/(в) k+100).

### RC-6 (BLOCKED Q-RC-RUNCONF-01) — краткий провал HV до подтверждения Run
- После k HV Faulty TRUE на 1 скан и на 20 мс внутри окна до Run. (а)/(б): Run в момент,
  определённый вариантом, если HV в норме в этот скан; (в): отсчёт с конца провала (нет Run на
  конец+99, Run на конец+101). Для (в) — судьба watchdog 30 с (вопрос).
- Не Emergency, не SafetyFault ни в одном варианте (провал HV до Run не является потерей Healthy
  в Run; Q-ARCH-03 касается LV) — **наблюдение**, не oracle, до ответа.

### RC-7 (READY, по FBK-03 v4) — дребезг C2_FBK
- C2_FBK FALSE в t_f+1 / t_f+50 при сохраняющейся команде C2, до Run → Emergency (EMGREF-RUN),
  Run не подтверждается. От Q-RC-RUNCONF-01 не зависит. Источник: Q-RC-19, FBK-03.

### Запрещённые реакции (все READY)
Run при C2_FBK OFF; Run при HV Faulty TRUE; Run ≤ u+99; ожидание 5 с / STO FBK; SS1/выбег
в StartingRun без события спуска; повторное поднятие STO при штатном подтверждении.

### Аварийные сочетания (без изменений, ссылки)
EStop/NC/connector в окне u…Run → EMGREF-RUN / IL-05a / EMG-004 (v4); LV норма теряется → abort
StartingRun (Q-ARCH-03, STP-I); истечение 500 мс / 30 с → WDG-03.
