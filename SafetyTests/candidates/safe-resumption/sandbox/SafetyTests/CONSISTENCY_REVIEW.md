## Согласованность документов

Нормативные документы согласованы по ключевым решениям:

- Последнее относящееся к сценарию решение пользователя имеет приоритет;
  reference задаёт сохраняемую полную последовательность. R&D добавляет
  устойчивую остановку и продолжение, а не разрешает redesign.
- StartingRun R&D→Run снимает STO при принятом launch без ожидания C2/HV
  Healthy feedback. Остальные разрешения и отдельное подтверждение Run
  сохранены. Инъекция accepted-request не доказывает external acceptance.
- SINGLE0.5/BOTH1 утверждены, заданные SAL timers не меняются.
  D-Q500 симметрично отдаёт single приоритет при второй кнопке ровно500мс;
  chord возможен до500мс. Green по-прежнему снимает Unlock; длительность
  видимого импульса в совпавшем скане не выдумана.
- Все41 требования обязательны; текущая частичность/отсутствие покрытия
  не выдаются за PASS. Аппаратная/native validation не скрытый gate.
  Обычные программные globals/связи разрешены по плану, аппаратные/групповые
  конфигурационные параметры запрещены. Неизвестные реакции идут аналитику.

Документальный пакет пригоден для архитектуры независимых исправлений.

## R1 — исполняемый oracle границы ещё устарел

Существенно для синхронизации тестового пакета, не блокирует независимый
LV permission пакет. На момент сверки candidate-button-cover.js задаёт
`stagger <= 500` как ожидаемый StepUp для ACC-B03-EDGE после1000/1010мс.
candidate-acceptance-runner.test.js требует EDGE PASS. Это старое inclusive
правило, противоречащее D-Q500: принятая single на500мс не превращается
в StepUp из той же попытки. SOFTWARE_ACCEPTANCE_SCOPE.md честно помечает
эти сценарии «требуют sync D-Q500»; текущий агрегат116/54 не означает,
что новый граничный контракт уже проверен правильно.

Исправление: подготовить Armed через полный release, покрыть обе очередности
на490/500/510мс; EDGE500 и LATE510 ожидают отсутствие retrospective StepUp,
а490 допускает chord только после BOTH1. Green-first отдельно проверяет
single acceptance; blue-first различает квалификацию и green-gated output.
Не добавлять требование видимого same-scan Unlock pulse. Сохранить остальные
отрицательные проверки и повторный полный прогон с честными FAIL.
Если внутренний marker single acceptance не определён, выбрать технически
обоснованную наблюдаемую связь, не подменять сценарий новым поведением.

## Неблокирующие замечания

Evidence matrix сохраняет старые строки о physical polarity/commissioning,
но явный текущий scope и раздел superseded запрещают делать их gate.
При следующем обновлении таблицы желательно пометить эти фразы историческими
непосредственно в строках. Исторические модели1/2с и inclusive500 помечены
историческими и не переопределяют новые решения; зависимые модели ещё должны
быть синхронизированы отдельно, их зелень не приёмка SAL.

Полное сопоставление сохранённых фаз reference по коду — задача реализации
и её ревью, а не доказанный факт из одной согласованности документов.
Пробелы Network4/group lifecycle должны закрываться программным доказательством
для обязательных сценариев; аппаратный/native gate не добавляется.
